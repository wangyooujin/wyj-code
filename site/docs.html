架构、能力与安全模型

首页只回答「要不要试」，这里回答「它到底怎么做的」。

Principles

设计原则

01

本地优先

没有隐式埋点、没有崩溃上报，配置与会话数据全部留在本机。

02

透明可控

每一次工具调用全程实时展示，敏感操作前弹权限确认，随时可以 ESC 打断。

03

协议中立

vendor 与 wire protocol 分离，同一兼容协议可服务不同厂商，不把模型名称猜测当成最终事实。

04

零遥测

只有显式的 LLM / WebFetch / MCP 调用才会出网，没有任何后台上报。

Features

核心能力

从推理循环到交互体验，每一层都是为终端场景重新设计的。

国内模型可信运行时

GLM、MiniMax、Kimi、DeepSeek、Qwen、豆包按能力来源和置信度适配；静态兼容与 live verified 明确分开。

可控的多 Agent 协作

进程级 Hub 管理并发、前后台调度、follow-up、interrupt、retry-last 与落盘 trace，控制消息只在安全边界注入。

Hooks 生命周期自动化

PreToolUse / PostToolUse / UserPromptSubmit / Stop 四个节点可挂任意 shell 脚本，对齐真实 Claude Code。

可插拔 MCP

内置 Bash / Read / Write / Edit / Glob / Grep / WebFetch / WebSearch / TodoWrite，并可桥接任意外部 MCP server。

内置网页搜索 WebSearch

配一个 Key 就有：Tavily / Brave 双后端、主题与时效窗口、按域过滤，搜索结果可直接交给 WebFetch 读全文。未知 provider 显式报错，未配 Key 则不注册。

上下文自动压缩

token 数逼近窗口上限时自动生成摘要替换旧消息，长会话也不会突然断档。

项目规约文件（AGENTS.md / CLAUDE.md）

每轮重新读盘注入、子目录动态加载、@path 递归导入，跨会话记忆同样开箱即用。

证据化自进化

v0.2.14 用 Episode、可验证 Memory、人工审批 Rule/Skill 候选和原子回滚形成透明闭环；Web/MCP 外部上下文默认隔离。

原生 ratatui TUI

流式 markdown、语法高亮、工具调用实时展示、子 Agent 聚合面板，交互体验为终端而生。

能力诊断与安全 Key 引用

model doctor 展示 vendor/protocol/能力来源；api_key_env 避免运行时 secret 被写回配置。

Checkpoint / Rewind / Branch

保留真实 Git index，按 conversation/files/both 恢复，并从任意 checkpoint 创建不影响原会话的新分支。

自定义 Slash 命令

兼容 ~/.claude/commands/*.md 与项目级命令，六层路径合并加载。

中 / 英双语

界面文案运行时切换语言，自动检测系统 locale，也可在配置中显式指定。

Fail-closed OS Sandbox

macOS Seatbelt + 受控域名代理、Linux bubblewrap；headless、schedule 与 SubAgent 无 UI 时拒绝隐式放行。

Computer-use 桌面控制

模型可观察并操控本机 GUI（macOS / Windows）；v0.2.14 允许 headless/daemon 安全执行截图、窗口枚举和元素检查，点击、输入、滚动及未知动作仍失败关闭。

Workflow + 隔离 Worktree

DAG 支持并行、预算、审批、暂停、重试与取消；有写权限的编码节点从脏工作区 checkpoint 自动创建独立 worktree，变更需显式 review/accept。

ACP / daemon 控制面

stdio ACP 与本地 TCP daemon 共享前端无关事件协议；daemon session 跨连接存活，可重连、列出、提交、打断、rewind、branch 和关闭。

Plugin Runtime + LSP

插件可事务式贡献 hooks、styles、themes、channels、LSP、monitors 与 settings；真实 workspace/symbol 与本地索引合并。

本地 Review 证据

review run 对 commit/PR diff 生成可审计 JSON，处理 rename、空格路径和 binary，并对 secret evidence 脱敏。

Jev 决策 API（v0.2.22）

TypeSafe System One 决策模型作独立 tool：意图路由 / 分类 / guardrails / 置信度标注，输出结构化 answers + probabilities；/decision slash 命令做连通性诊断，三层硬封顶（state 大小 / question 数 / 日预算）防失控。

Built-in Web Search

内置网页搜索 WebSearch

模型的知识有截止日期，你的代码库没有。WebSearch 让它在动手之前先去查「现在这个 API 到底怎么用」「这个 CVE 影响哪些版本」「最新版有没有 breaking change」——查完再动手，而不是拿训练时的记忆硬写。

它是内置的：不是需要自己起的 MCP server，不是让模型自己拼 curl 的 shell 命令，而是和 Read / Grep / WebFetch 并列的一个正式工具。配一个搜索服务的 API Key，模型立刻就多出一双能看世界的眼睛。

三分钟启用

在全局配置里加一段 [search] 就行。

# ~/.wyj-code/config.toml
[search]
provider  = "tavily"   # 或 "brave"
api_key   = "tvly-xxxxxxxx"
max_results = 5        # 硬上限 10

不想把 Key 写进文件，就用环境变量——环境变量的值不会被写回配置文件：

export WYJ_CODE_SEARCH_API_KEY="tvly-xxxxxxxx"

重启后敲 /doctor，看到这一行就算好了：

  ✓  网页搜索    tavily

没配 Key 时工具压根不注册——模型看不到一个注定失败的入口，不浪费一次 LLM 往返。provider 名字写错则显式报错，绝不静默回退到默认后端。

它能做什么

  • · 主题与时效：topic 支持 general / news / finance，time_range 支持 day / week / month / year——查「今天」「本周」的版本发布与安全通告
  • · 按域收敛：include_domains / exclude_domains 限定官方文档、issue tracker、源码仓库，屏蔽 SEO 农场；配置里的默认白/黑名单模型可临时覆盖
  • · 双后端：Tavily（带 LLM 生成的问答式摘要与相关度评分）、Brave（带 safesearch 与 search_lang）。后端不支持某参数时明确报错而不是静默忽略
  • · 搜索 → 深读两步接力：搜索给「标题 + 链接 + 摘要」，模型再用内置 WebFetch 读全文，同一轮里完成
  • · Key 只进请求头：body 会被代理日志完整打印，头不会。瞬时故障退避重试一次，限流与认证错误不重试
  • · 外部文本按不可信处理：结果统一过 harness marker 转义，网页正文伪造不了对话结构；超长输出落盘，模型可用 Read 取回

开发者最常用的四个场景

01

升级依赖前先查 breaking change

「cargo update 之前先搜一下 ratatui 0.30 有哪些 breaking change。」模型先搜官方 release notes 与 issue，列出风险点，再决定动不动 Cargo.toml。

02

排查只在最新版出现的报错

「这个 400 unknown parameter 错误只在最新版本出现，搜一下是不是已知的 upstream issue。」拿到 issue 编号与讨论串，再回到你的代码里定位。

03

查框架的当下最佳实践

「现在写 Rust HTTP 服务，官方推荐哪种错误处理中间件？」搜索把过时的博客答案和当前官方文档分开，模型按需 WebFetch 读全文。

04

安全通告与依赖漏洞

「我们用的 rustls 版本有没有已知的严重漏洞？」搜 CVE 与发行说明，输出带链接的清单——可审计、可复查。

Security Model

仓库能往你上下文里塞什么，边界在哪

这一章记录 wyj-code 的信任边界设计决策。核心问题很具体：你 git clone 一个陌生仓库，对方就能往你的目录里放文件——而 AI 助手的部分文件是纯文本指令，内容会作为模型指令进入对话。哪些文件可以自动生效，哪些必须先问你，是这一章的全部内容。

涉及信任门控的扩展点有三处：mcp.toml（会执行任意命令）、.wyj-code/skills/（正文是指令）、settings.json 的 hooks 与 verify.command（会被 sh -c 执行）。三处现在都有显式批准流程——hooks 的门控在 v0.3.12 补上：指纹只覆盖 hooks.*.command 与 verify.command 两个键，批准记录落仓库外，内容变化后需重新批准。

v0.3.15 · 思考强度跨协议打通、官方端点不再缺臂、同 chunk 不再丢字

本次改动的共同判据：思考强度应该是一个旋钮，而不是每家端点各自实现的一套死配置。本版五件事分落三层：目录与协议、响应解析、配置与轮数。

① 官方 Anthropic 原生支持 effort。此前 AnthropicNativeAdapter 只读 thinking.budget_tokens，reasoning_effort 在 Anthropic 线上是死配置——换个协议就得改一份配置。现在 ThinkingSpec::anthropic_native(model) 按型号给档位集合（Opus 4.8/4.7/5 系五档全量、4.6 到 max、4.5 到 high、3.x/4.0 不支持→记成可见 dropped），adapter 发 output_config.effort；新增 budget_and_effort_coexist 表达两个旋钮控制不同维度：budget 限思考的 token 数，effort 限整个响应的投入档位。

② 官方 OpenAI（o 系列 / gpt-5 系）此前完全没有臂。缺 (OpenAiChatCompletions, "openai") 分支时，effort 一路被 catalog 判成 Unsupported、在到达 provider 之前就被滤成 None——配了等于没配。现在只发顶层 reasoning_effort、绝不写 thinking / enable_thinking / thinking_budget（官方判未知参数直接 400），echo_back_in_messages 必须为 false（官方既不回传也不接受 reasoning_content），档位不收 minimal（gpt-5.1+ 不认）。

③ 响应侧 reasoning 字段名二选一。reasoning_content（DeepSeek / GLM / Qwen 的既有约定）与 reasoning（vLLM / SGLang / GPT-OSS / OpenRouter 的新约定）同时收——只认前者会让整条新线思考永不可见；同 chunk 两者都非空时择一而非拼接（拼接即重影）。解析 ≠ 回传：vllm / ollama 响应里有这个字段，但回传会 400。

④ 同 chunk 多字段不再互斥。stream_events_from_chunk 此前把 finish_reason / content / tool_calls 写成一条 else if 链，只处理第一个命中者——端点把正文与 finish_reason 合并进同一 chunk 时，正文被静默丢弃，表现为「模型明明说了话，界面少一段正文」。现在三者互不排斥，发射顺序固定 reasoning → content → tool_calls → MessageStop：收尾信号必须最后。

⑤ 配置面与轮数上限。profile 面板的 reasoning_effort 由 OpenAiWire 改为两条线都显示——Anthropic 线此前根本不显示该字段，用户无从配置，这正是「Anthropic 线上 effort 是死配置」在 UI 层的根因；--config-status 新增 max_tokens 超过静态目录输出上限的提示（目录给的是保守下限，只提示、不静默改写）；思考关不掉的端点同样压到 32 轮。
