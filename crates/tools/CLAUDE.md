# crates/tools 规约

本文件是 `crates/tools/CLAUDE.md`。**按目录惰性加载**：只有当工具触达
`crates/tools/` 下的文件时，加载器才把它拼进 system prompt
（`core::claude_md::ClaudeMdLoader::maybe_dir_reminder`，按目录去重、每会话只展示一次）。
根目录 `CLAUDE.md` 只留跨 crate 的通则与索引，本目录的实现细节全部沉在这里。


## 工具输出溢出（spill）

`tools::spill`：超限输出**落盘**而不是直接丢弃中段。`spill_truncated(text, head, tail, label)` 在 `text.len() > head + tail` 时把全文写进 `<config_dir>/spill/<毫秒戳>-<label>-<hash8>.txt`（0600，写入前过 `wyj_core::redact_sensitive_text`），返回文本保留原 `[truncated N bytes]` 标记并把路径并进同一行——模型据此可以 `Read`/`Grep` 那个文件按需取回任意片段，而不是重跑命令（`cargo test` / `npm install` 重跑一次就是几分钟，还可能已产生副作用）。

三条不变式：① **落盘失败绝不改变工具结果**——`write_spill` 返回 `None` 时退回纯截断（`truncate_head_tail` 的原样输出），不报错、不降级成空串；② **返回值不比截断更大**：路径并进原标记行，不额外增加行数；③ **不做内容去重**：文件名带时间戳，同一命令重跑两次落到不同文件，避免并发下"刚才那个文件"被另一个调用改写。目录内超过 7 天的文件在下次写入时顺手清掉（`SPILL_TTL_SECS`），避免 `spill/` 无限增长。

接入点：`bash.rs`（stdout / stderr 各自独立落盘，预算仍是 `MAX_OUTPUT` 的 6:4 头尾）、`webfetch.rs`（`MAX_CONTENT = 50_000` 时按 7:3 落盘——网页正文的有效信息常常在中后段，只留开头会丢掉结论）。与 `core::context_edit` 分工不同：那边处理**历史里已经存在**的工具结果（事后 CAS 外部化 + `ContextRecall`），这边处理**刚刚产生**的输出（事前落盘 + 普通 `Read`）。

## WebSearch：可插拔后端与「显式失败」

`tools::search`（`mod.rs` + `tavily.rs` + `brave.rs`）把 WebSearch 拆成「工具层做校验与渲染、后端层只发请求」两层，`SearchBackend` trait 只有 `name` / `supports_topic` / `search` 三个方法：

- **构造唯一入口是 `build_backend(cfg)`**：未知 provider **显式报错并返回 `None`**（绝不静默回退到默认后端），未配置 key 也返回 `None` —— 这两种 `None` 的语义不同，由 `Config::search_provider_issue()` 给出面向用户的解释（`/doctor`、`--config-status` 共用同一判定）。返回 `None` 时工具**不注册**，模型看不到一个必然失败的工具。
- **参数非法一律报错**：`topic` / `time_range` 解析失败直接回 `ToolResult::err`；后端不支持 `topic`（Brave 只有 freshness）时也**明确拒绝**而不是悄悄降级成通用搜索——「模型以为在搜新闻、实际拿到通用结果」比报错更糟。
- **域名过滤**：配置 `[search].allowed_domains` / `blocked_domains` 是**默认值**，模型显式给 `include_domains` / `exclude_domains` 时**覆盖**（不是并集：并集会让模型既无法临时放开黑名单，也无法收窄白名单）。两处都过 `clean_domains`（去 scheme / 路径 / 前导 `*.`、小写化、去重）。
- **错误分类决定「下一步该谁做」**：`Auth` / `BadRequest` 直接回灌模型（重试无用）；`RateLimited` 保留 `Retry-After` 秒数；只有 `Transient` 退避重试一次。超时与 UA 由 `[search].timeout_secs` 与固定 UA 构造的 `reqwest::Client` 承担。
- **输出侧**：结果先拼装、再 `escape_harness_markers`（搜索结果来自不可信网页，不能让它伪造 harness 标记）、最后 `spill_truncated` 落盘（7:3 头尾，与 `webfetch` 一致）。Tavily 没有分页标记，`more_available` 恒 false；Brave 按「返回条数 == 请求条数」推断。
- 注册点三处共用 `build_tool_registry`：主 Agent（`cli::assembly`）、子 Agent 工厂（`cli::make_sub_agent_factory`）、`/model` 重建。三处都必须带 `with_default_domains(...)`，漏一处就是「主 Agent 生效、子 Agent 不生效」的静默漂移。

## Grep 工具的两级实现

`tools::grep` 刻意做成**两级、对外行为一致**的搜索后端，测试里 `assert_both_ways` 对同一输入断言两条路径的输出一致：

- **rg 快路径**（默认，`rg_binary` 只在 `PATH` 里探测一次）：直接 spawn `rg --color=never --no-heading -H --hidden --no-messages -g '!.git' -g '!.git/**' -e <pattern> -- <root>`，流式读 stdout，命中 `head_limit`/500 匹配上限后 `kill` 掉子进程（不读完，避免白扫整棵树）；`files_with_matches`/`count` 模式额外按路径排序，抵消多线程遍历的乱序。三条硬约定：① 子进程 `RIPGREP_CONFIG_PATH=""`，否则用户自己的 rg 配置（如 `--smart-case`）会静默改变匹配语义；② `-H` 必须带，否则 rg 搜索**单个文件**时默认只打行号不打路径；③ rg 插在相邻上下文组之间的 `--` 分隔符要剔除（原生实现不输出它）。rg 退出码 ≥2（非法 pattern/glob）视为「rg 搞不定」，回退纯 Rust。
- **纯 Rust 兜底**（没装 ripgrep 的机器）：`ignore::WalkBuilder::build_parallel()`（线程数 = `available_parallelism`，上限 16，命中上限后 `WalkState::Quit`）+ regex-automata 字面量预筛。预筛用 `regex_syntax` 在 Hir 上抽字面量（`Prefilter::new(MatchKind::LeftmostFirst, …)`，memchr/memmem）：**先整文件字节级粗筛**，没有候选就连二进制 NUL 扫描与 UTF-8 校验都省掉，再逐行过滤后才进 regex 引擎。大小写不敏感时必须用 `ParserBuilder::case_insensitive(true)` 解析出**已折叠**的 Hir 再抽字面量——不能把 needle 简单转小写，那会漏掉 ſ/İ/K 这类 Unicode 折叠特例造成**静默漏报**；抽不出字面量或模式可匹配空串时返回 None，退回逐行 `is_match`，宁可慢不能漏。

**忽略语义两条路径必须一致**（这是改造的另一半收益）：跳过 `.git` 目录、`.gitignore`/`.ignore`/`.git/info/exclude` 在任何目录都生效。旧实现 `hidden(false)` 会把 `.git/objects` 一起遍历（本仓库 710 个文件里 473 个是 `.git` 内部文件），且 ignore crate 的 `require_git` 默认 true，非 git 仓库里 `.gitignore` 静默失效。

**用户可见的后端标注**：`grep::backend_label()`（经 `wyj_tools::grep_backend_label` 导出）返回本次会走的分流结果（`"rg"` / `"native"`），判据与 `rg_backend` 同源、共用同一份 `PATH` 探测缓存。TUI 用它在工具行尾部补后缀（`⏺ Grep(pat in .) · rg`，i18n key `tool_backend.rg` / `tool_backend.native`，见 `tui::app::tool_backend_badge`）——工具名对模型可见，光看 `Grep(...)` 分不出这次到底谁在跑。注意它表达的是「会走哪条路」而非「这次确实跑完了 rg」：rg 起来后自己报错（退出码 ≥2 且无输出）仍会静默退回纯 Rust，标注来不及更正。

实测（release、Apple Silicon）：本仓库常规搜索 10~30×；832MB/3 万文件的语料上全量扫描 rg 快路径 4~11×，纯 Rust 兜底 2~7×。纯 Rust 兜底在大文件全量扫描时仍受「整份 read 拷贝」限制（~600MB/s），没有走 mmap——`memmap2::Mmap::map` 是 unsafe 且文件被并发截断时会 SIGBUS（进程直接死），不值得为兜底路径冒这个险。


## SubAgent 工具与后台 shell


7. **SubAgent 多 agent 编排**（对齐 Claude Code）：类型体系 = 内置 general-purpose/Explore(只读)/Plan（`core::agent_def::builtin_defs`）+ 自定义定义文件（四层合并链，v0.2.24 起由 6 层简化：`内置 → 全局 ~/.wyj-code/agents → 插件贡献(先到先得) → 项目 .wyj-code/agents`，frontmatter: name/description/tools/model，model 引用 **Profile 名**，同名后者覆盖，`load_agent_defs`）。wyj-code **不读取** `~/.claude/agents/` 或 `<cwd>/.claude/agents/` 等任何外部源。`tools::SubAgentTool`（工具名 "Agent"，参数 subagent_type/description/prompt/run_in_background）把每个子 Agent 整体 `tokio::spawn` 并登记进 `tools::agent_hub::SubAgentHub`（进程级单例：id 分配、`Semaphore` 并发上限 8（`[subagent].max_concurrent` 可配）、`abort_foreground`/`abort_all`/`wait_background`）；子 Agent 挂 `with_tool_callback`/`with_usage_callback` 把内部工具事件与 token 用量以 `SubAgentEvent` 汇入 Hub 的 event_cb。前台调用 await oneshot 结果；`run_in_background: true` 立即返回，完成结果包成 system-reminder 经注入通道（主 Agent 忙）或 `AppState.pending_bg_reminders`（空闲，下轮起手 merge）送达。TUI 展示：每个 agent 的 ToolCall 行绑定 sub_agent_id（Started 事件 FIFO 配对）并在运行期间画动态 ⎿ 状态行（耗时/tokens/工具数/当前工具），聊天流中的 ToolResult 默认折叠成工具标题行、与 thinking 共用 `Ctrl+O` 全局展开出全文（对齐 Claude Code）；前台 Bash 是唯一例外中的例外——它经 `ToolContext::tool_output()` 把 stdout/stderr 的**累计尾部快照**（100ms 一帧、`try_send`、满则丢）推进 TUI，执行期间在 ⏺ 行下方实时展开，跑完即收起（渲染层细节见 `crates/tui/CLAUDE.md`）；完整内部工具调用与最终结果通过 SubAgent 独立详情面板查看。有运行中 agent 时显示底部聚合面板（`render::draw_sub_agents_panel`）。ESC 中断只 abort 前台子 Agent，后台不受影响；TUI 退出时 `abort_all`，headless `-p` 结束前 `wait_background`。子 Agent 模型解析优先级：def.model(Profile 名) → `[subagent].explore_profile`(仅 Explore) → `[subagent].default_profile` → 主 Agent 当前分组（`cli::make_sub_agent_factory`）。子 Agent 注册 `Agent` 但要受 `[subagent].max_depth` 限界（默认 3 层；v0.3.x 起改为**触顶时不再注册**该工具，而不是留一个每次调用都报错的工具——模型看到工具没了才会自己干完）；其余 AskQuestion/ExitPlanMode/TodoWrite 一律不注册，并继承 Plan 白名单交集。工具集裁剪走 `select_sub_agent_tools`：先按 `disallowed_tools` 减（支持 `mcp__server` / `mcp__server__*` 整组屏蔽），再按 `tools` 白名单取交集；`omit_claude_md` 的定义（内置 Explore/Plan）不挂 `ClaudeMdLoader`——本仓库规约上万 token，对探索任务一次都用不上。`/agents` 列出全部类型；`/cost` 单列子 Agent 用量。

    **子 Agent 执行轨迹持久化**（v0.1.5）：`SubAgentHub::emit()` 是 TUI/headless 唯一汇聚点，`with_trace(sessions_dir, session_id, max_bytes_per_agent)`（`SubAgentCfg::trace_enabled` 默认开启）在此接入一个专职后台写手（`tools::trace::TraceWriter`，内部 mpsc channel 串行 append，调用方零阻塞），把 `SubAgentEvent` 转成落盘用 `TraceEvent`（`ToolStart`/`ToolEnd` 补全完整 input JSON / output 全文，`textutil::truncate_str`/`truncate_head_tail` 截断，超过 `trace_max_bytes_per_agent`（默认 256KB）静默停写）写入 JSONL：`~/.wyj-code/sessions/<session_id>.subagents/a<id>.jsonl`（与 `SessionFile` 不共享结构，不污染 `api::types::Message`/`ContentBlock`）。`Started` 事件带 `parent_tool_use_id`（经 `Tool::run_with_meta`/`ToolCallMeta` 从 `exec_tool_call` 的 `tool_use_id` 透传，仅 `SubAgentTool` override，其余工具零改动）关联回会话消息里的 `ContentBlock::ToolUse.id`。TUI 启动/`-c`/`--resume` 统一路径下 `app::reload_persisted_sub_agents` 扫描该目录回灌 `AppState.sub_agents`（只填摘要级字段，全文仍留在磁盘，避免长会话常驻内存暴涨），天然复用现有面板与 `/subagents [id]` 命令（无参数定位最近一个，带 id 直接跳转，`headless_unsupported` 提示改用 CLI 子命令）。headless 侧 `wyj-code subagent-trace <session_id> [<sub_id>] [--json]`（`cli::run_subagent_trace_cmd`）纯读打印落盘内容，无 sub_id 列出该会话全部子 Agent 概览。

    **交接物**（v0.3.8，`tools::handoff`，设计见 `doc/plan/subagent-handoff-plan.md`）：与 trace 同目录、后缀不同的 `a<id>.handoff.json`（`list_trace_ids` 只挑 `.jsonl`，既有解析不受影响）。结构 `SubAgentHandoff{status: Completed|Interrupted|TurnLimit|Failed, reason, conclusion, digest, elapsed_secs}`；`digest` 由 `ToolDigest{files_read, files_modified, commands, searches, errors, total_calls}` 组成，运行期 `record_start`/`record_error` 累积，与 `from_trace` **共用同一套提取规则**（两条路径不能漂移）。三处写入：① 正常结束/失败/触顶由任务自己组装（结论优先取本轮 `output_buf`，为空才回退扫描 messages）；② **ESC/abort 由 Hub 侧补写**——`abort()` 取消 future 后任务收尾不再执行，所以 `HandoffProgress` 共享快照必须边跑边记（每轮 `record_turn_text`、每次工具 `record_tool_start/error`），`register_with_handoff` 把它与 `HandoffMeta` 一起登记；③ 未配置 `sessions_dir` 时静默跳过。trace 同步新增 `TraceEvent::Assistant{text}`（每轮末文本，保头 4KB）——`ToolStart/ToolEnd` 只说明「读了什么」，说明不了「由此得出了什么」，而结论不可再生、原文可再生。注入走 `prompts::subagent_handoff_body`（三选一封闭枚举），前台与后台经 `SubAgentEvent::Done.handoff_body` 共用同一份渲染结果。**明确不做 resume**。

    **消息增量日志**（`tools::message_log`，与交接物互补而非替代）：上面三条写入路径**都要求进程还活着**——`SIGKILL`、关终端、断电、OOM killer 时一行收尾代码都不会跑。`a<id>.messages.jsonl` 解决这一档：`Session::message_sink` 在每条消息进入 `messages` 的**同一刻**回调，后台写手 `MessageLogWriter` 串行落盘（与 `TraceWriter` 同构、调用方零阻塞），`SubAgentTool::with_message_log` 把它挂到子 Agent 的 `Session` 上。三个事件而非「一条消息」是必须的：`Appended` / `UpdatedLast` / `Replaced`——`push_user_blocks_merged`（工具结果合并）与 `prepend_to_last_user`（每轮规约注入）都**原地改最后一条 user 消息**，只追加不认改写会让日志永久停在残缺状态；压缩与 context editing 是**整段替换**，必须打 `snapshot` 锚点，否则重放会把压缩前后拼成一个从未存在过的历史。读侧 `replay()` 从最后一个 snapshot 起算，半行（被 kill 时最后一行）跳过并置 `incomplete`。`recover_progress()` 是硬杀场景的兜底入口，`subagent-trace` 在「没有交接物但日志有内容」时打 `no handoff (process killed before cleanup)` 并吐出最后一轮 assistant 文本。开关跟随 `[subagent].trace_enabled`。**注意它只是恢复现场，不是恢复会话**：子 Agent 仍然不会被 resume，主 Agent 拿到的依旧只有结论。


## Computer-use 桌面 GUI 控制


15. **Computer-use 桌面 GUI 控制**（v0.2.1，`tools::computer::ComputerTool`，`#[cfg(any(target_os = "macos", target_os = "windows"))]`）：`ApiTool` 走 `wyj_api::types::ToolDefinition.native: Option<NativeToolSpec>` 分支序列化，**双模式**由 `ComputerTool::new(max_dim, native: bool)` 的 `native` 参数决定，`run()` 的动作分派逻辑两种模式完全一致，只是对外声明方式不同：
    - **native=true**（原生模式）：声明为 Anthropic 原生 `computer_20251124` 工具——`{type, name, ...extra}`，无 description/input_schema，provider 层按 `native.beta` 追加 `anthropic-beta: computer-use-2025-11-24`（见 `api::anthropic::build_api_tool`/`collect_beta_header`）。仅官方 api.anthropic.com 认得这个空 schema 工具类型（Claude 训练时习得的调用约定）。
    - **native=false**（custom 模式）：声明为普通 custom 工具，`description`/`input_schema` 是真正发给模型的内容——`descriptions::computer_custom_description(target_width, target_height)` 动态嵌入实际下采样分辨率，完整列出全部 action 字段（无 Claude 那层内置训练兜底，必须自解释）。任何具备基本工具调用能力的模型都能按标准协议使用，用于第三方 Anthropic 协议兼容端点（MiniMax/GLM/Kimi 等）。
    - 注册门控（`cli::register_computer_tool_if_enabled`，main.rs 初始 registry 与 `/model` 重建 `rebuild_fn` 两处调用）：平台 `#[cfg]` + `Profile.vision` + `provider == Anthropic`（Messages API 协议本身才有 tool_result 内嵌图片的回传通路；OpenAI Chat Completions 的 `tool` 角色不支持图片，`openai.rs` 会把截图降级成占位文本，注册了也是名存实亡）缺一不注册；是否用原生声明另由 `Profile::is_official_anthropic_endpoint()` 决定（`provider == Anthropic` 且 `base_url` 为空或等于官方地址，与 `effective_prompt_cache()` 共用同一判定）——**教训**：早期版本把"是否注册"和"native == Anthropic"这两件事合并成一次判断，导致 MiniMax 这类走 `provider = "anthropic"` + 自定义 `base_url` 接入的第三方端点，要么被误判成官方端点收到无 schema 的原生工具直接 400，要么被整体拒绝注册、功能完全不可用；现在拆成"注册与否看协议、原生与否看端点"两层判断，两种情况都能正确工作（详见 `doc/plan/v0.2.1-plan.md`）。子 Agent 工厂不注册（与 Agent/AskQuestion 一致）。
    - 系统层 `wyj-computer`：仅截取主显示器，物理像素按 `scale::fit_within(max_dim)`（默认 `computer::DEFAULT_MAX_DIM = 1280`，与 Anthropic 官方博客推荐的默认分辨率一致）下采样后编码 PNG，`ToolResult::with_parts` 携带 `ToolResultPart::Image` 回传（复用 Read 工具已验证的图片回传链路，见下方 Read 相关说明）；模型给出的坐标基于下采样后的目标分辨率，执行前经 `scale::CoordScaler::to_physical` 换算回物理像素，`cursor_position` 动作反向经 `to_target` 换算回模型坐标系。
    - **教训（Retina/HiDPI "点" vs "像素"，`zoom` 截图缺内容的根因）**：macOS 上有两套并不相同的坐标系——`xcap::Monitor::width()/height()`（底层 `CGDisplayBounds`）返回的是"点"（逻辑分辨率），而 `capture_image()` 实际截到的 `RgbaImage` 是原生像素分辨率，Retina 屏上通常是点数的 2 倍；`enigo`（`CGEvent`/`NSEvent.mouseLocation`）的全局光标坐标系统一用"点"，这部分本来是对的，不用改。早期实现里 `capture_region`（`zoom` 动作的底层）直接把"点"坐标系下钳制好的裁剪矩形（`scale::clamp_region` 的结果）传给 `image::DynamicImage::crop_imm` 去裁"像素"图，2x Retina 屏上只能裁到请求区域左上角 1/4 的面积，静默丢失其余 3/4 内容——这正是"截图时有些内容没截到"的根因，且在这台真实开发机（点分辨率 1920x1080、像素分辨率 3840x2160，scale_factor=2.0x）上被 `crates/computer/examples/zoom_fix_probe.rs` 真机复现确认。修复：`crates/computer/src/scale.rs` 新增纯函数 `scale_region_to_pixels(region, logical_size, pixel_size)`（可单测，覆盖 identity/2x 缩放/局部区域按比例换算/四舍五入越界钳制/零维度兜底五种场景），`capture_region` 先按"点"坐标系钳制（不变），再用它换算成像素坐标系后才 `crop_imm`；`capture_primary`/`capture_window_by_name`/`capture_region` 三处都改为直接用已捕获图像自身的 `img.width()/height()` 作为 `encode_capture` 的 physical 尺寸（不再信任 `Monitor`/`Window` 的 `width()/height()`），因为图像对象自己报告的尺寸永远和它自身像素数据一致，不存在"点/像素"混淆的可能。**`ComputerTool.physical_width/height`（`primary_display_size()` 产出，用于点击坐标 `CoordScaler` 映射）刻意保持不变、仍然是"点"**——这是唯一正确选择，因为 `enigo` 的点击坐标系本就是"点"，如果也"修正"成像素会导致点击坐标整体偏移 scale_factor 倍、完全点不准；`Capture.physical_width/height`（每次截图/裁剪返回值里的字段）经排查确认全仓库只用于工具结果里的展示文案（如 `"[screenshot: 1512x982 -> ..."`），从未被用作坐标换算依据，因此可以安全地改为报告真实像素尺寸而不影响点击链路——这是这次修复能够"只改截图/裁剪路径、不碰点击路径"从而保持改动范围可控的关键前提。
    - **`zoom` 动作**（提升识别准确率）：`wyj_computer::capture_region`/`scale::clamp_region` 截取主屏后裁剪到指定物理像素矩形，只在裁剪结果仍超过 `max_dim` 时才下采样——多数"放大看细节"场景裁剪区域远小于 `max_dim`，因此有效分辨率远高于全屏缩略图里的同一块内容，用于看清全屏截图下采样后会糊掉的密集数字表格/小字。`ComputerTool::do_zoom` 解析 `region: [x0,y0,x1,y1]`（目标坐标空间，四周自动加 `ZOOM_PADDING_RATIO=0.12` 余量防止切边），归入只读 action（`is_read_only_action`），不需权限确认，且和 `screenshot` 一样重置连续动作计数。原理依据 2025-2026 GUI agent 研究（RegionFocus/UI-Zoomer/GUI-Eyes 等，测试时动态裁剪放大可带来两位数百分点的 grounding/OCR 准确率提升）与 Anthropic 官方 computer-use 博客的"按需请求细节而非提高全屏分辨率"建议；`wyj_core::prompts::COMPUTER_USE_HINT` 与 `descriptions::computer_custom_description()` 都教模型"读数字前先 zoom，别猜"。
    - 权限：后台 `app_computer` 的 `list_windows/screenshot/inspect_element` 只读放行，`click/set_text/key/scroll` 走既有 `confirm_tool`；旧 `computer` 只有 `[computer_use].foreground_fallback = "ask"` 时变更动作才弹确认，`disabled`（默认）直接返回 `requires_foreground_takeover`，`idle_only` 仅按安静期执行。`computer`/`app_computer` 是 `PROJECT_APPROVE_ONCE_TOOLS`：首次按 y/Enter/a 都会分别写入当前项目的 `allowed_tools.json`，同项目后续动作和重开项目不再确认，不同项目仍隔离；拒绝不落盘。终端 TUI 无法渲染截图像素（纯文本终端），仅模型可见画面。
    - **系统提示追加**（`COMPUTER_USE_HINT`）：强制模型优先 `window_capture list/capture → app_computer`，稳定传递 `window_id + generation + target dimensions`；禁止在 `target_changed/requires_foreground_takeover/preempted_by_user/user_active/input_monitor_unavailable/screen_locked` 后自动重试或自行切换旧 `computer`。打开应用仍优先 Bash，读取用户自己的屏幕内容仍是普通截图任务、不需要应用 API。
    - **点击类动作的修饰键支持**：`left_click`/`right_click`/`middle_click`/`double_click` 复用通用 `text` 字段传入要按住的修饰键组合（如 `"shift"`、`"cmd"`，语法与 `key` 动作一致），对齐 Anthropic 官方 computer-use 工具的调用约定（shift-click 多选等场景）。`ComputerTool::do_click` 点击前 `wyj_computer::key_down`、点击后（无论点击成败）`key_up`，优先向模型报告点击本身的错误、释放失败作为次要错误兜底报告，避免修饰键状态残留污染后续操作。系统层 `wyj_computer::key_down`/`key_up`（`backend.rs::parse_key_combo` 共享解析）允许中间插入其他操作（如鼠标点击），因为按键按下/释放状态存在于操作系统层面，不依赖是哪个 `Enigo` 实例发出；`key()` 本身就是 `key_down` 紧接 `key_up`。`summarize_action` 权限确认弹窗摘要同步展示修饰键（如 `left_click at (10, 20) holding shift`）。
    - **`/computer` 诊断命令**（`commands::builtin::ComputerCmd`，i18n key 前缀 `computer.*`）：只读诊断，不依赖真的注册了 `ComputerTool`。门控判断逻辑（平台 → vision → provider）与 `register_computer_tool_if_enabled` 保持一致但独立复现（`crates/commands` 不依赖 `wyj-tools`，直接依赖 `wyj-computer`），再加是否为官方端点判断真实/custom 模式；平台受支持时额外做三项实时探测：`wyj_computer::primary_display_size()`+`scale::fit_within` 算目标分辨率、`capture_primary(64)` 真实截一次小图验证屏幕录制权限、`cursor_location()` 验证辅助功能权限链路可达。固定附带一条 macOS 辅助功能提醒：`cursor_location()` 读取成功不代表点击/按键一定生效——未授权时 `Enigo::new()` 往往仍成功、事件被系统静默丢弃且不报错，这种失败模式没有错误可捕获，只能靠固定文案兜底。
    - **v0.2.5 人机互不干扰架构**：根治方案不是继续调 idle 阈值，而是把后台目标化执行设为默认、全局前台输入降级为显式兼容模式。
      - `computer::target::WindowTarget{window_id,pid,bounds,generation,...}` 由 `xcap::Window` 构造；generation 对窗口身份/标题/逻辑边界做稳定 FNV-1a 哈希。`window_capture` 支持 `list/capture`，截图结果返回稳定 id、generation 与图片坐标空间；旧 `query` 仅保留首次发现兼容，后续不得重复模糊匹配。
      - macOS `tools::app_computer` 是默认写路径：`click` 优先用限定目标 PID 的 AX hit-test + `AXPress`，`set_text` 优先 settable `AXValue/AXSelectedText`，`key/scroll` 最多通过带 marker 的 `CGEventPostToPid` 定向投递；每次动作前后通过系统级 AX 精确校验前台 PID；若某 App/动作在无人类输入时仍抢前台，本会话立即熔断该组合。目标窗口若已在前台，还额外要求配置的连续安静期。
      - **v0.3.6 起：AX 路线改为「优先 + 显式降级」，不再硬失败**。起因是实测（微信 v4.1.15，原生 AppKit 自绘）确认 AX 对自绘应用**必然**失效：窗口内 5×5 网格 hit-test 25/25 返回 `kAXErrorNotImplemented(-25208)`（访达 36/36 命中作阳性对照），而 `CGEventPostToPid` 的**鼠标**事件虽送达目标进程却因 `window == nil` 被 AppKit 静默丢弃（键盘事件不受影响，不经窗口服务器命中测试）。旧规约那句「绝不静默回退」正是让微信这类应用寸步难行的原因。现三级降级：坐标 `click` = AXPress → `cursor_click::execute`（跳过去、点、**无条件**用 RAII 复原光标，不改前台应用）；坐标 `set_text` = AXValue → `targeted_event::type_char` 逐字符定向按键（**仅 ASCII 可打印字符**，非拉丁文本走这条路必然失败，必须显式报错而非静默丢字）；坐标 `scroll` = AX 语义滚动 → 定向 PID 滚轮，且降级必须覆盖「hit-test 本身就失败」这一档（那是 `Err` 而非 `Ok(false)`，`?` 会短路掉后面那级）。
      - **降级不等于放松安全边界**：`cursor_click` 仍要求调用方先拿 `InputLease`、事件带 `INPUT_EVENT_MARKER`（不被本进程 Event Tap 误判成用户抢占）、执行前后校验前台 PID（变了即 `preempted_by_user`）、光标位置**无条件**复原（含中途出错）。变的是「可不可以降级」，不是「降级要不要守规矩」。工具 `description` 必须写明降级存在及其限制——模型要能预判点了会发生什么、知道光标会被短暂借用。
      - `computer::activity` 是进程级 `InputArbiter`：enigo 与目标 PID 事件统一写入 `INPUT_EVENT_MARKER`，被动 session Event Tap 忽略该 marker，以 seqlock 维护真实外部输入的 `external_event_seq/last_external_at` 和最近事件环形缓冲。前台接管中任何人类输入都立即撤销 `InputLease`；后台目标化动作则按事件类型/全局坐标只拦截可能影响目标窗口的键鼠事件，因此用户持续在其它 App 输入或移动鼠标时 Agent 仍可并行工作。Event Tap/Input Monitoring 不可用、事件历史丢失或 Tap 短暂失效时统一失败关闭，不再用 `last_own_input_at + grace_secs` 猜测。
      - 旧 `computer` 只做 foreground compatibility：`[computer_use].foreground_fallback = disabled|ask|idle_only`，默认 `disabled`；变更前要求真实 TUI 交互通道、精确 monitor、连续安静期和与最近全屏截图完全一致的前台窗口，观察在动作尝试前即消费，且只在租约仍有效时按需恢复原前台 App 与指针。headless/cron/子 Agent 一律禁止前台接管；`type` 分小块并在块间校验租约，拖拽/组合键异常路径尽力释放全部按键。旧 `ComputerUsePaused` TUI 面板/`confirm_resume` 通路已删除，用户不再被动作级暂停弹窗打断。
      - cron 不再因为用户活跃而整体跳过：后台工具可以安全并行，旧前台工具在 headless 内部自行硬拒绝。Windows v0.2.5 先提供稳定窗口截图与默认关闭的前台兼容边界，后台语义操作留待平台后端实现。
      - `/computer` 同时报告后台支持、AX 授权、InputArbiter 状态/错误、前台回退配置、稳定窗口数量、截图与全局输入诊断，以及只存在当前进程内的后台/目标 PID/前台路径和安全熔断计数；`automatic_foreground_fallbacks` 是显式恒零不变量，不写磁盘、不外发 telemetry。
