Quickstart

最小可用配置

总共三行：端点协议、模型名、Key 走环境变量。其余全是默认值，不写就生效。

# ~/.wyj-code/config.toml
provider = "anthropic"
model = "claude-opus-4-8"
context_window = 200000   # 必须填真实值

Key 建议走环境变量

export WYJ_CODE_API_KEY="sk-..."

环境变量优先级最高，且永远不会被写回 config.toml——即使你之后打开 /profile 面板保存了一次。想落盘又不想写明文，就配 api_key_env = "MY_KEY_VAR" 引用变量名。

最容易犯的错：把 context_window 填成一个未验证的超大值。压缩阈值与清理阈值都由它推算——填成 1,000,000 而实际只有 200k，两套保护等于从未运行，工具输出会全量累积、每趟重发整段历史。--config-status 对 >500k 的值会给告警。

Layout

文件与数据根

数据根默认 ~/.wyj-code，可用 WYJ_CODE_HOME 整体指向外置盘。它是进程级决定，所有子系统一致生效。

<data_root>/
├── config.toml  settings.json  AGENTS.md  installed.json
├── skills/  agents/  plugins/  marketplaces/  model-capabilities/
├── sessions/<project_key>/       # 会话 + .checkpoints/ + .subagents/
├── history/<project_key>/history.jsonl
├── memory-v3/{global,projects/<key>}/
├── evolution/<project_key>/  indexes/<project_key>/
├── workspaces/<project_key>/  workflows/<project_key>/
├── projects/<project_key>/
│   ├── allowed_tools.json  mcp_trust.json  skill_trust.json  hooks_trust.json
│   ├── instances/  meta.json
│   └── skill-data/<skill>/       # 项目级 skill 的可写产物
└── cas/  spill/  logs/

project_key 怎么算

形如 v1-wyj-code-1f367bbfb19407b9（目录名 + SHA-256 前 16 位），按 git 仓库根归一。同一仓库的任意子目录、以及带 --project-root 指回主仓库的 worktree，都归到同一个 key——所以从 src/ 启动仍能看到根目录的会话与授权名单。

storage.scope：状态跟不跟着仓库走

"home"（默认）全部放数据根；"project" 把会话、历史、项目层记忆、演化、代码索引改放 <git-root>/.wyj-code/local/，并自动写两道 gitignore。选它的理由是「换机器 / 换 clone 就带走对话历史」，代价是 transcript 里是工具输出原文——漏一次 git add -A 就是永久泄漏。信任门控目录与 CAS 池永不跟随：前者必须在仓库控制不到的位置，后者是跨项目去重池。

从旧版升级

旧数据仍在数据根时功能不会坏（读取有兜底），但建议跑一次迁移：wyj-code storage migrate 只报计划，加 --yes 实际搬迁（rename，同盘原子）。无法确定归属的条目报 skipped 并保持原样。

Profiles

调用分组 [[profiles]]

一个分组 = 一套完整的「端点 + 凭据 + 能力」。TUI 里 /profile 管理整套分组（写盘），/model 只切当前分组下的模型（仅内存），/effort 管思考档位（随会话落盘）。三者职责刻意分开。

字段类型 / 默认值说明
name"default"分组名，组内唯一。--profile <name> 可一次性指定本次运行用哪套，不改变全局默认。
provider"anthropic" / "openai"选择客户端实现，线协议由它唯一决定。vendor 不再单独配置，由 base_url + 模型名推断。
model"claude-opus-4-8"默认模型。auto 与 plan 模式在未配专用模型时都用它。
plan_model""Plan 模式专用模型，留空回退 model。/model 在 plan 模式下只改这个字段。
exec_model""Auto / Bypass 模式专用模型，留空回退 model。两者共用同一个字段——差别在权限判定，不在模型能力要求。
aux_model""辅助模型，只作用于两个调用点：会话标题生成、跨会话记忆提取。它们各自用独立短 system prompt，不复用主对话前缀，因此换模型不会打穿主会话缓存。上下文压缩绝不用它——压缩要逐字节复用主前缀来命中缓存，换模型等于缓存归零、整段历史全价重发。
base_url""端点地址，留空用供应商默认。第三方兼容端点填到 /anthropic 或 /v1 一层即可。
api_keynull明文 Key，不推荐。落盘后文件会被设为 0600，但仍是明文；优先用下一行或环境变量。
api_key_envnull引用一个环境变量名，运行时取值。推荐：配置里只有变量名，密文留在 shell / 密钥管理器里。
max_tokens32000单轮输出预算。思考 token 也计在内——推理模型的预算黑洞常在这里。输出被吃满且无可见内容时会放大预算重试一次。
context_window200000模型真实上下文窗口，必须填真实值。压缩硬阈值 = window - max(max_tokens+8192, window/10)，清理软阈值 = window × 0.55，都由它推算。它是裸 u32，没有 live probe 兜底。
visiontrue模型是否支持图片输入。false 时图片降级为占位文本，避免非多模态端点收到 image 块直接 400。
thinking_budgetnull扩展思考预算 token。0 / 不写 = 关闭。思考计入 output 计费。
interleaved_thinkingtrue工具轮之间允许交错思考。Anthropic 线专属——OpenAI 线不发该 beta，配了也不生效。生效前提是本轮真的发出了 thinking 字段。
prompt_cachenull（跟随端点）null = 按端点类型判定：官方 Anthropic 开；第三方 Anthropic 兼容端点（MiniMax / GLM / Kimi）默认关——它们实现了 cache_control，但对未知 anthropic-beta 头常直接 400，故第三方开启时只发 cache_control、不发 beta 头。端点连 cache_control 也不认时首次 400 自动降级，并在 /cost 显示原因。
openai_stream_optionsnull是否发 stream_options.include_usage。null = 按端点自动判断；不认这个字段的兼容端点显式关掉即可。
reasoning_effortnull思考投入档位 low / medium / high / xhigh / max，协议无关：OpenAI 线发顶层 reasoning_effort，Anthropic 线发 output_config.effort。端点不认的档位记成可见的 dropped 而不是发出去换 400。生效优先级：env > 会话级 /effort > 本字段。
thinking_switchnullOpenAI 线 thinking.type 显式覆盖：enabled / disabled / adaptive。不写 = 由 adapter 按模型默认决定（MiniMax M3.1 发 disabled 会 400，adapter 会降级成不发该字段）。
max_tools_per_turnnull每次回复最多并行几个工具调用。null = 由模型目录 / 探测结果决定，而静态目录对非 anthropic/openai vendor 一律判 1——MiniMax / GLM / Kimi 等实际能并发的端点会被静默锁成每轮一次往返。这个字段是逃生舱：model doctor --probe full 通过后显式放开。

旧字段会被静默忽略：vendor 与 wire_protocol 已移除（vendor 改为推断、协议由 provider 决定）。旧 config.toml 里留着这两行不会报错，下次 config.save() 时随 profiles 数组整体替换而消失。

Top Level

顶层字段

字段类型 / 默认值说明
active_profile"default"当前激活的分组名，必须在 [[profiles]] 里有同名项，否则回退到第一项。
log_level"warn"日志级别，调试时设 "debug"。/config 面板也能改它。
language""（自动检测）"en" / "zh"。留空按系统 locale 检测。它同时决定 UI 文案与模型输出语言（含 thinking）——解析结果会进 system prompt 的 <env> 块。
auto_memory_enabledtrue跨会话记忆自动提取。/memory 面板可切换。关掉后不再每轮后台提取，但已有 claim 仍可检索。

Search

[search] 内置网页搜索

它是内置工具，不是 MCP server、不是让模型自己拼 curl。没配 Key 时干脆不注册这个工具——模型看不到一个注定失败的入口，不浪费一次 LLM 往返。

字段类型 / 默认值说明
provider"tavily"后端：tavily / brave。写成未知值会显式报错，绝不静默回退——否则你会以为自己用的是 Brave。
api_keynull后端 Key，优先读环境变量 WYJ_CODE_SEARCH_API_KEY（env 值不会写回本文件）。Key 只进请求头，绝不进请求体——body 会被代理日志完整打印。
timeout_secs30单次搜索请求超时（秒）。瞬时故障退避重试一次；限流 / 认证 / 参数错误不重试。
max_results5模型未显式指定时返回的条数，硬上限 10。
allowed_domains[]默认白名单域名。模型可用 include_domains 覆盖（不是并集）——并集会让模型既无法临时放开黑名单，也无法把白名单收窄。
blocked_domains[]默认黑名单域名，模型可用 exclude_domains 覆盖。常用它屏蔽 SEO 农场。
language""Brave 的 search_lang（ISO 639-1），留空用后端默认值。Tavily 忽略此项。
safe_searchtrue安全搜索，Brave 映射为 safesearch=strict。

Runtime

Agent 循环与子 Agent

[subagent]

字段类型 / 默认值说明
default_profile""子 Agent 默认使用的分组，留空沿用主 Agent 当前分组。
explore_profile""内置 Explore 类型的专用分组（配便宜模型很划算），留空回退 default_profile。
trace_enabledtrue是否把子 Agent 完整执行轨迹落盘。日志是进程被硬杀时唯一的恢复来源。
trace_max_bytes_per_agent262144单 agent trace 文件上限（默认 256 KiB），超限静默停写。交接物与消息增量日志不受此上限约束。
max_depth3子 Agent 最大嵌套层数（主 Agent 之下算第一层），1 = 禁止嵌套。触顶时 Agent 工具会从该层子 Agent 的工具集里消失，而不是留着报错。
max_concurrent8同时运行的子 Agent 上限，超限的 spawn 排队等待、不失败。

[agent]

字段类型 / 默认值说明
max_turns200单次用户提交内允许的最大推理轮数（一次 LLM 往返 = 一轮）。默认 200 的本意是「防模型死循环」，不是给正常长任务设工期。距上限还剩 4 轮时会先注入收尾指令，要求模型停止调用工具、立即总结进度——触顶不再等于失败。调高它买「单轮能推进多远」，代价是单次提交的最长耗时与 token 上限；死循环保护由 loop_guard 独立承担。
forced_thinking_max_turns64思考关不掉的端点（reasoner / -r1 / MiniMax M2.x-M3.1 / Qwen·豆包 -thinking / Moonshot -code）的单回合熔断轮数。默认比 max_turns 保守得多：这类端点几乎「一轮一个工具调用」，实测单回合能跑到 163 轮 / 35.6 万 output token / 半小时以上。v0.3.19 之前写死 32，代价是中型任务必然撞顶、每次都得手打「继续」。

[tools]

字段类型 / 默认值说明
todo_enabledtrue是否注册 TodoWrite 任务列表工具。未注册 = 工具不产生 schema，模型目录里根本看不到它。改回默认开启的理由：长任务里模型没有外部状态锚点，压缩一发生就不知道自己走过哪条路，而 TodoWrite 是唯一能穿透压缩的显式进度载体。简单任务为主或强模型跑短任务时设 false 更划算。

[ui]

字段类型 / 默认值说明
mouse"auto"鼠标报告三态：auto 按 TERM 判定（只有缺失、空串或 dumb 才关）/on/off。默认开的原因：alternate screen 里终端没有自己的滚动条，而 macOS Terminal.app 不支持 DEC 1007——不开捕获时滚轮完全没反应。开启后滚轮、拖选、双击选词、滚动条拖动全部由应用实现，选完自动复制到剪贴板。
mouse_capturenull（废弃）v0.3.18 前的布尔字段，等价于 on/off。仍被识别但不再写回，下次保存配置时消失。
scrollbartrue内容区右侧是否绘制应用内细滚动条（│/┃）。只在内容超出视口时出现，宽度 < 3 列的终端不画；出现后可拖动滑块或点击轨道跳转。

Context

[context_edit] 上下文清理优先于摘要

超阈值时先把过期工具输出外部化到 CAS（无损，可召回），清理得动就不跑整段摘要。摘要是有损的，而且贵；外部化只是把原文挪到磁盘并留一个可取回的占位符。

字段类型 / 默认值说明
enabledtruefalse = 完全退回旧行为（只压缩、不清理）。
protect_recent3最近 N 个工具结果保留全文。刚看过的输出正在被引用，挪走等于让模型重新读一遍。
batch_size10单批清理条数。每批都会击穿一次 prompt cache 前缀，批太大浪费命中率。
min_result_bytes2000小于此字节数的结果不清理——省下的 token 还不够一条占位符本身。
max_batches3单次请求最多连续清理几批，防止「历史里全是可清理项」时一次做掉大手术。
soft_limit_ratio0.55软阈值：占用超过窗口这个比例就开始外部化，而不是等撞上压缩硬阈值。0 = 关闭。为什么需要它：1M 窗口下硬阈值在 900K，实际会话永远够不着，清理逻辑等于从未运行。软阈值只改「何时开始」，不改「何时停手」——降到硬阈值以下才停；清理不动了仍然交给压缩。

Storage

[storage] 容量与回收

全部字段 opt-out：设 0 即关闭对应清理，保持旧行为。删除历史不可逆，因此所有会删数据的项默认都不删——想清就自己设阈值，或手动跑 wyj-code storage prune。

字段类型 / 默认值说明
checkpoints_per_session20单会话 checkpoint 上限，超限按时间淘汰最旧的。
memory_v2_md_per_kind200Memory v2 每类 .md 文件条数上限。
memory_v3_records_max5000Memory v3 records.json 条目上限。Superseded 状态永远保留，只对 Active / Pending 淘汰；淘汰按「写入新鲜度 × 0.30 + 使用强度 × 0.70」打分——只按更新时间截断会把「三个月没改但每次开工都要查的约定」先删掉。使用强度依赖访问计数，计数走增量日志 access.json，GC 在截断之前先合并日志。
memory_v3_jobs_max32Memory v3 pending 任务队列上限。
memory_v3_rejected_history_max500已拒绝项的指纹表条数上限——它的作用是防止同一个候选被反复提议。
plugin_gc_interval_days7插件 .git 做 git gc --prune=now 的间隔天数。
workspace_worktree_max_age_days30workspace worktree 自动 prune 的过期天数。
disk_usage_warn_bytes5368709120启动期占用告警阈值（默认 5 GiB）。只在启动日志里 warn 一次，不阻塞。
cas_max_blob_bytes16777216CAS 单 blob 上限（默认 16 MiB）。超此值的文件不进 CAS，直接 inline 进 checkpoint JSON。
cas_total_bytes1073741824CAS 总量上限（默认 1 GiB）。启动时按 LRU 回收 ref_count == 0 的 blob；会话结束时逐个 release，两个机制缺一都会让 pool 无界增长。
cas_gc_on_starttrue启动时是否跑一次 CAS gc。blob 很多时是全池目录遍历（毫秒级），可关掉省这一步。
sessions_ttl_days0会话保留天数，默认 0 = 永不自动删除。删历史不可逆，不该在升级后的第一次启动里静默发生。想启用就设 30 / 90。
sessions_keep_recent5每个项目无条件保留最新 N 条。TTL 的必要配套：纯 TTL 会把「三个月没动的项目里唯一那批会话」删光，而那恰恰最想回看。
stale_lock_ttl_days7删 cas/locks/ 与 sessions/*.lock 里无人持有且超期的。内核会释放 flock，但文件本身不会被删——实测能攒到上万个 / 几十 MB。
scope"home"运行状态落盘范围：home / project。用字符串而非枚举：未知值降级为默认并告警，而不是让整份 config.toml 解析失败。

Persist Cap

[persist_cap] 单块内容上限

同一组上限作用于三条路径：落盘（save / checkpoint）、运行时发送给模型、resume 读回。共用一套值是为了避免「落盘截断了、运行时没截断」这种不对称——长文本块在内存里无界累积会直接撞穿模型上下文窗口。0 = 不截断该项。

字段类型 / 默认值说明
tool_result_head_bytes20480工具结果文本的 head 上限。
tool_result_tail_bytes10240工具结果文本的 tail 上限。保留尾部是因为报错和总结几乎总在最后。
thinking_bytes0（废弃）已废弃，不再生效，保留字段仅为兼容旧配置。原实现按此截断 thinking，但协议要求续轮时把 thinking 块原样回传——截断文本却保留 signature 会让签名校验失配，且该改写不可逆。思考体积改由 context_edit / compact 控制。
reasoning_details_bytes0（废弃）已废弃，不再生效，理由同上；额外考虑是原实现会改 text 却保留 id/format，产出结构不自洽的块。
tool_use_input_bytes65536工具调用参数的 JSON 字符串上限。
text_head_bytes16384纯文本块的 head 上限。默认比 tool_result 更紧：文本信息密度低，长 assistant 总结与用户粘贴的日志都在这里。
text_tail_bytes8192纯文本块的 tail 上限。

Auto Mode

[auto_mode] 谁来决定问不问你

wyj-code 只有一个日常模式 auto（旧的 manual 已并入它，作为兼容别名保留解析）。判定顺序是硬性的：受保护路径 deny → 确定性 allow → 确定性 hard_deny → 模型分类器 → 交回逐次弹窗 → 降级。

永远自动放行（零延迟、零成本）

工作目录内的文件写、只读 shell 命令、构建 / 测试命令、lockfile 依赖安装。本地字符串判定，不发模型请求。

任何模式都不放行

curl | bash、rm -rf ~、git push --force、git reset --hard、terraform destroy、sudo <program>、凭据路径（~/.ssh 等）、写入受保护路径（.git/、.env、*.pem、~/.wyj-code/）。bypass 模式也不豁免——它免的是「询问」，不是「禁止」。这一层挂在 PermissionPolicy::evaluate，不读任何授权状态：授权只能免除问人，不能免除禁令。

字段类型 / 默认值说明
enabledtrue模型分类器总开关。false = 只保留本地确定性规则层，拿不准的一律逐次弹窗（保守模式）。两条确定性规则排在分类器开关之前，否则关掉分类器时 curl|bash 只剩一个弹窗、按个 y 就过去了。
classifier_profile""分类器用哪个分组。留空 = 复用当前激活分组（此时它的 token 计在主会话里）；填分组名 = 用它单独跑，适合配一个便宜的小模型。
timeout_secs30单次分类请求超时。默认 30 而非更小：adaptive thinking 端点光思考就要好几秒。超时与「解析失败」是同一个 fail-closed 出口。
max_consecutive_blocks3连续被判定拒绝达到该次数 → 自动停用分类器，改为逐次弹窗。
max_total_blocks20整个会话累计被拒达到该次数 → 同样降级。
classify_all_shellfalsetrue 时所有 shell 命令一律送审，不走本地 allow 白名单——更安全，但每条命令都多一次模型往返。
hard_deny[]英文自然语言规则（喂给分类器，不是正则）。数组里出现字面量 "$defaults" 就在该位置插入内置规则，因此自定义项可写在默认项之前或之后，并继续继承后续版本的内置规则更新。不写 "$defaults" 会整段替换内置规则——对 allow / environment 通常正是你想要的，对 hard_deny / soft_deny 则会实打实放宽拦截面，启动日志会就此告警。
soft_deny[]同上。软拒绝：分类器据此判断「这一步虽然在用户大方向上，但这条具体命令不该跑」。
allow[]同上。用于放行项目特有的安全操作，例如「允许部署到 staging：它与生产隔离且每日重置」。
environment[]同上。描述你的环境事实（版本控制宿主、云厂商、部署目标），分类器据此判断某条命令是否越界。

放行记忆的粒度按工具分叉

Bash 按工具名：批准一次后本轮所有 Bash 免问（长任务里几十条同类命令不该各付一次往返），闸门在复用前仍逐条走 hard_deny 与只读白名单。其余工具按输入指纹：Edit 批过 notes.md 不该顺带放行 deploy.sh——用户在为一个文件点头，不等于同意改另一个。

Notify

[notify] 回合结束提醒

三件事共用一条通道：主回合完成、主回合出错、后台子 Agent 完成。零新第三方依赖——终端响铃走 \x07，桌面通知走 macOS osascript / Linux notify-send / Windows PowerShell BurntToast。

字段类型 / 默认值说明
enabledtrue总开关（opt-out）。
rate_limit_seconds30同类事件的最小发送间隔去重，0 = 关闭限流。
include_session_idfalse是否在通知正文末尾追加 [session:<id>]。默认关：正文很短，加前缀反而挤掉内容。
bell.enabledfalse终端响铃，opt-in 默认关——TUI 常开在共享屏幕上，响铃容易扰民。
desktop.enabledtrue桌面通知，opt-out 默认开。后台子 Agent 跑完时你多半已经切走了窗口。
events.turn_finishedtrue主回合正常完成（TUI / REPL / -p）。
events.turn_errortrue主回合出错。
events.subagent_donetrue后台子 Agent 完成（run_in_background: true）；前台调用不通知。

Evolution

[evolution] 证据化自进化

每个用户目标落盘为一个 Episode，从中生成带 scope、citation、TTL、冲突检测的 Memory，以及 Rule / Skill 候选。候选永不自动激活，必须经 /evolve 或 wyj-code evolve approve 显式批准。

字段类型 / 默认值说明
enabledtrue总开关。关掉后完全不记录 Episode、不生成候选。
use_experiencestrue是否把历史经验纳入提取上下文。
suggest_rulestrue是否产出 Rule 候选。
suggest_skillstrue是否产出 Skill 候选。
auto_activate_rulesfalse默认 false，不建议打开：Rule 会进 system prompt，自动激活等于让模型自己改自己的行为约束。
auto_install_skillsfalse同上，Skill 自动安装默认关。
allow_self_code_experimentsfalse是否允许对自身代码做实验性修改，默认关闭。
exclude_external_contexttrue是否把 Web / MCP 等外部上下文排除在演化证据外。默认排除：外部内容不是用户意图的证据，混进来会污染偏好学习。
infer_feedbacktrue是否从后续对话推断隐式反馈（用户重述或修正即负反馈）。
skill_candidate_min_successes3Skill 候选所需的最少成功次数。
skill_candidate_min_sessions2Skill 候选所需的最少独立会话数——一个会话里重复三次只是同一件事做久了。
idle_delay_secs300空闲多久后才跑后台演化（秒），避免与前台回合抢模型配额。
max_background_workers1后台演化并发 worker 数。
max_context_bytes8000单次演化提取喂给模型的上下文字节上限。
max_daily_tokens50000演化每日 token 预算，硬封顶。
max_daily_wall_secs1800演化每日墙钟预算（秒），默认 30 分钟。
max_project_store_bytes104857600单项目演化数据目录上限（默认 100 MiB），超了走 retention。
evolution_profile""演化调用用哪个分组，留空 = 复用当前激活分组。
retention.repository_fact_stale_days28仓库事实（模块职责、构建命令）多久后算陈旧。
retention.workflow_stale_days60工作流记忆的陈旧期。
retention.user_preference_review_days180用户偏好多久后进入复审（不直接删，偏好过期不该被当成错误）。
retention.failed_episode_days30失败 Episode 保留期。
retention.candidate_days90未处理的 Rule / Skill 候选保留期。
retention.audit_days180审计记录保留期。

Routing

[routing] 与 [model_runtime]

路由单元是 Profile 名而不是裸模型 id——每个候选要能携带自己的 vendor、协议、端点与能力配置。默认禁止跨 vendor fallback：把同一份对话在用户未授权时发给另一家供应商，与「辅助模型必须同端点」守的是同一条边界。

字段类型 / 默认值说明
routing.cross_provider_fallbackfalse是否允许在可恢复错误时跨供应商切换。默认 false。
routing.roles.explore[]Explore 角色的候选分组链，按顺序尝试。空 = 用当前激活分组。
routing.roles.plan[]规划角色的候选链。
routing.roles.execute[]执行角色的候选链。
routing.roles.review[]评审角色的候选链。
model_runtime.probe_mode"explicit"能力探测模式。默认保守：未经探测的能力一律标 static_only，不假装已验证。
model_runtime.probe_ttl_hours168探测结果缓存有效期（默认 7 天），过期后需 doctor --refresh 重探。
model_runtime.tool_argument_retries2工具参数解析失败后的重试次数（弱模型常产出半截 JSON）。0 = 不重试，直接把错误回灌给模型。
model_runtime.lazy_tools_threshold12工具总数超过该值时启用 lazy schema：核心工具给完整 schema，其余走 ToolSearch 按需展开。工具少时全量给更省一次往返。
model_runtime.lazy_tools_top_k8lazy 模式下一轮最多展开几个候选工具。
model_runtime.lazy_tools_sticky_turns3命中的工具在搜索结果里排序加权的回合窗口。v0.3.14 起不再控制可见性：工具数组物理排在 prompt cache 前缀最前面，中途摘工具会让整段缓存失效，因此可见性改为单调不减。

Computer Use

[computer_use] 桌面 GUI 控制

computer / app_computer / window_capture 三个工具默认在 macOS / Windows + vision = true 时注册。后台工具优先：前台接管必须显式配置，不能在后台动作不支持时悄悄降级去抢用户的鼠标键盘。

字段类型 / 默认值说明
foreground_fallback"disabled"旧 computer 工具的前台兼容策略三档：disabled 变更动作直接返回 requires_foreground_takeover；ask 每次变更弹一次确认（要求真实 TUI 交互通道，headless / 子 Agent 一律拒绝）；idle_only 只在用户持续空闲时执行。三档都仍受输入仲裁器与前台 PID 校验约束。
quiet_period_ms2000获得前台输入租约前，必须连续没有外部输入的时长。
max_defer_secs30等待用户空闲的最长时间，到期失败关闭，不强行执行。
restore_contexttrue前台兼容动作结束后是否尝试恢复原观察上下文。
auto_screenshottrue变更动作成功后是否自动附一张目标窗口截图。这是「动作 → 观察」闭环的核心：模型不必自己再调一次 screenshot 才知道界面变了没有（它经常不会，于是拿着过时的界面继续往下点）。代价约 1000~1600 input token / 次。关掉也不会关掉整条验证链——连续 20 次变更动作无截图时仍强制附一张。
auto_screenshot_max_dim960自动附图的长边像素上限。刻意低于观察用的 1280：附图只回答「界面变了没有」，要看清小字时模型会显式 screenshot 或 zoom。

MCP

[[mcp_servers]] 外部工具服务

全局写在 ~/.wyj-code/config.toml，项目级写在 <git-root>/.wyj-code/mcp.toml（同名覆盖全局、不同名追加）。项目级条目需显式信任批准——它们随 clone 落地，并且会执行任意命令。

字段类型 / 默认值说明
name必填服务名，用于日志区分与项目级覆盖判定。
transport"stdio"stdio / streamable_http（旧写法 "http" 仍被接受）。
commandnullstdio：可执行命令。
args[]stdio：参数列表。
env{}stdio：附加环境变量。
urlnullstreamable_http：远端端点。
headers{}streamable_http：请求头。值支持 ${ENV_VAR} 引用，渠道凭据不必写进文件。

Project

项目级配置 <git-root>/.wyj-code/

这一层可以提交、随 clone 落地，因此「能被仓库作者控制的内容」必须过信任门控。批准记录一律落在仓库控制不到的位置（~/.wyj-code/projects/<key>/）——放进仓库等于让仓库自己改掉批准标记。

路径用途
settings.tomldisabled_skills / disabled_mcp_servers 按名禁用开关。
settings.jsonHooks、verify、acceptance 三段（可被 settings.local.json 追加覆盖）。
mcp.toml项目级 MCP server，需 wyj-code trust-mcp 批准。
skills/项目级 Skill 与自定义命令（name.md 或 name/SKILL.md），需 trust-skills 批准。
agents/项目级 SubAgent 定义。
local/仅当 storage.scope = "project" 时出现；自动写 gitignore。

编辑后自动验证

声明 verify.command 后，每次 Edit / Write 成功返回，Agent 立即跑这条命令，把退出码与截断后的输出回灌给模型，让它自己看到编译/测试错误并继续修。没声明时零代价：不探测、不启 shell、不产出任何输出。

验收门禁

「任务完成」不再由模型自己宣布。声明 acceptance.criteria 后，模型想结束回合时框架先跑一遍判据；不通过就不让结束，并把失败证据（文件与行号，不回显匹配内容）回灌。判据配错时恒判不通过——被静默跳过的判据比明确失败更危险。

// .wyj-code/settings.json
{
  "verify": {
    "command": "cargo test -p wyj-core",
    "timeout_ms": 120000
  }
}
// .wyj-code/settings.json
{
  "acceptance": {
    "max_retries": 2,
    "criteria": [
      { "id": "tests-pass", "kind": "command",
        "command": "cargo test" },
      { "id": "no-debug", "kind": "grep_absent",
        "pattern": "dbg!\\(", "paths": ["src"] }
    ]
  }
}

三处信任门控，逐类批准

mcp.toml（执行任意命令）、skills/（正文是指令）、settings.json 的 hooks 与 verify.command（被 sh -c 执行）三处都有显式批准流程：wyj-code trust-mcp / trust-skills / trust-hooks，或 trust 一次批三类。批准一次即可：内容不变就不再问；内容变了会列出具体变化的文件。skill 指纹覆盖 skills/ 整棵树（含 references/）——那是经由已批准 SKILL.md 可达的二阶注入面。运行产物请写 $WYJ_CODE_SKILL_DATA，写回自己的目录会让刚批准的信任失效。

Environment

环境变量总表

下面这些只在运行时生效、绝不写回 config.toml。它们对应的运行时槽位带 #[serde(skip)]，正是为了「打开设置面板保存一次」不会把 secret 物化进文件。

变量作用备注
WYJ_CODE_API_KEY模型 API Key最推荐的填法；覆盖激活分组的 key，不落盘。
WYJ_CODE_SEARCH_API_KEYWebSearch 后端 Key未配置则不注册 WebSearch 工具，模型看不到它。
WYJ_CODE_PROBE_API_KEYmodel doctor --probe 专用 Key刻意不复用配置里的 Key：探针要多发请求，用户需自行轮换。
WYJ_CODE_HOME数据根目录默认 ~/.wyj-code；外置盘 / 独立测试环境用。
WYJ_CODE_THINKING_EFFORT思考档位优先级最高：覆盖会话级 /effort 与 profile 字段。off = 彻底关思考。
WYJ_CODE_THINKING_SWITCHOpenAI 线 thinking.typeenabled/disabled/adaptive，覆盖 profile。
WYJ_CODE_MAX_TOOLS_PER_TURN每轮最多并行工具数覆盖 profile；用于放开被静态目录误判成 1 的端点。
WYJ_CODE_NOTIFY_OFF通知总开关1 = 全关，最高优先级。
WYJ_CODE_NOTIFY_BELL覆盖终端响铃0 / 1。
WYJ_CODE_NOTIFY_DESKTOP覆盖桌面通知0 / 1。
WYJ_CODE_SKILL_DATA项目级 skill 的可写产物根前台 / 后台 Bash 都会注入；目录不预创建，需要时自己 mkdir -p。
WYJ_CODE_STREAM_IDLE_SECSSSE 流空闲多久判定卡死0 = 关闭看门狗。
WYJ_CODE_MCP_CALL_SECS单次 MCP 调用超时0 = 关闭。
WYJ_CODE_TURN_STALL_SECSTUI 回合停滞看门狗0 = 关闭。
WYJ_CODE_UPDATE_GOLDEN重新生成 TUI 快照基线仅开发用：=1 cargo test -p wyj-tui golden。

结构性参数（context_window、max_turns、storage.*）没有 env 覆盖——改配置应该改文件并留痕；env 只留给「这次运行换个开关」的场景。

Recipes

三段可以直接抄的配置

想省钱：辅助调用换小模型

[[profiles]]
name = "default"
model = "MiniMax-M3"
aux_model = "MiniMax-M3.1-Flash-Preview"

[auto_mode]
classifier_profile = "cheap"

两个辅助调用（标题生成、记忆提取）与权限分类器都不复用主对话前缀，换模型对主会话缓存零影响。压缩绝不用辅助模型。

长会话：让清理早点动手

[context_edit]
enabled = true
soft_limit_ratio = 0.45
protect_recent = 5

[storage]
cas_total_bytes = 2147483648

外部化是无损且便宜的（无 output token、不幻觉），越早动手，每趟携带的历史越小。CAS 池同时放到 2 GiB 兜住增量。

想更强：放开并发与档位

[[profiles]]
name = "fast"
provider = "anthropic"
reasoning_effort = "high"
max_tools_per_turn = 4
interleaved_thinking = true

[agent]
max_turns = 320

静态目录对国内 vendor 一律判「不支持并发工具」，这个字段是逃生舱；max_turns 调高买的是单次提交能推进多远，代价是最长耗时。

不知道从哪改起？先跑诊断

wyj-code --config-status 打印当前分组、Key 状态与超限告警；TUI 里敲 /doctor 看环境与扩展的健康度。
