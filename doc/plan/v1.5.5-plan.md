### 2.1 多图片与附件 Composer

已经存在的行为：

- 多张不同图片可连续粘贴并按粘贴顺序保存在 `pending_attachments`。
- 图片占位符显示为 `[Image #1]`、`[Image #2]`；文件附件不占用图片序号。
- 占位符只用于渲染，不混入发送给模型的正文。
- 真实文本清空且光标位于文本起点时，Backspace 从右向左逐个删除附件。
- `build_user_blocks` 按正文、图片 1、图片 2 的顺序构造模型输入块。

已经存在的自动化覆盖：

- 多次不同图片粘贴保持顺序。
- 先删除正文，再从右向左删除附件。
- 多图片按顺序发送为独立 `ContentBlock::Image`。
- 混合文件附件时图片编号连续且不被文件占号。

待真机验收：

- PNG/JPEG/剪贴板截图混合连续粘贴。
- 图片、文件、正文混合后在行首连续 Backspace。
- 只含附件时发送、Esc/Ctrl+C 清理、忙碌队列发送语义不回归。
- Anthropic/OpenAI-compatible 两种 provider 的图片块顺序一致。

### 2.2 滚轮伪方向键与输入历史隔离

已确认根因：Ghostty 在 alternate screen 且应用关闭 mouse capture 时，DEC mode 1007 可能把滚轮转译为传统 `ESC[A` / `ESC[B`；crossterm 随后把它们暴露为无修饰 `Up` / `Down`，Composer 的输入导航无法天然判断它们来自键盘还是滚轮。

已经存在的修复：

- 继续使用 `DisableMouseCapture`，保留终端原生拖选复制。
- Ghostty 直连路径启用 Kitty `REPORT_EVENT_TYPES`，通过真实按键具有 release/repeat、滚轮转译只有 press 的差异进行分流。
- 滚轮方向键 burst 只调用内容区滚动，不进入 `navigate_input_or_history`。
- 真实方向键经判定后回放，继续保留光标移动与输入历史语义。
- 非 Ghostty 或 tmux/zellij 路径不假定 release 事件可靠透传，成对保存、关闭、恢复 DEC mode 1007，至少保证滚轮不会污染输入历史。

已经存在的自动化覆盖：

- Ghostty 直连与 multiplexer 环境选择正确路由策略。
- 启动/退出时 Kitty 键盘增强标志与 mode 1007 序列成对恢复。
- 真实方向键在 release 后回放。
- 物理按键 repeat 回放初始 press 与 repeat。
- 滚轮 burst 只产生内容滚动。
- 单个待判定伪方向键在下一个非方向键到来前刷新到内容滚动。

待真机验收：

- Ghostty 直连：快速/慢速滚轮、真实 `↑/↓` 单击和长按、输入历史、中文多行编辑。
- Ghostty + tmux、Ghostty + zellij：滚轮不得进入 Composer；退出后终端 mode 恢复。
- Terminal.app、iTerm2 及至少一个 Linux 终端：原生选择、PageUp/PageDown、方向键不回归。
- 异常退出、panic、挂起/恢复后终端键盘协议与 mode 1007 不残留。

## 3. 网络调研：AI Coding 自进化的可复用实践

### 3.1 产品侧实践

#### OpenAI Codex：把重复经验放进正确的持久化层

Codex 当前官方最佳实践把长期改进拆成不同载体：

- 稳定、必须执行的仓库规则写入 `AGENTS.md`，并允许全局、仓库、子目录分层覆盖。
- 重复出现的工作流转成单一职责 Skill；先手工跑通，再固化，再考虑调度。
- Skill 使用渐进式披露：常驻上下文只放名称与描述，匹配后再读取完整说明。
- Skill 要分别测试应触发、间接表达、信息不全、不应触发和安全边界等样例。
- 后台定时任务适合已经稳定的流程，也可用于回顾近期摩擦并提出配置/指令改进。
- 并行或后台修改使用 Git worktree 隔离，最后通过 diff、测试与 Review 接收。

Codex 的本地 Memory 也明确把记忆定位为“辅助回忆层”，而不是必须执行规则的唯一来源；本地记忆生成与使用可分开控制，后台空闲时处理，生成字段要脱敏，并可选择排除使用过 MCP、Web Search 或 Tool Search 的外部上下文会话。

对 wyj-code 的含义：经验、规则、Skill、自动任务和核心代码修改必须分层；不能把任何一次对话反思直接当成最高优先级系统规则。

官方资料（核对日期：2026-08-04）：

- [OpenAI：Build skills](https://learn.chatgpt.com/docs/build-skills) —— Skill 渐进式披露、明确触发边界和代表性请求测试。
- [OpenAI：Custom instructions with AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md) —— 全局、仓库与子目录的持久规则分层。
- [OpenAI：Memories](https://learn.chatgpt.com/docs/customization/memories) —— Memory 是辅助回忆层；生成/使用分离、后台空闲生成、secret 脱敏与 external context 排除。
- [OpenAI：Worktrees](https://learn.chatgpt.com/docs/environments/git-worktrees) 与 [Scheduled tasks](https://learn.chatgpt.com/docs/automations) —— 后台任务隔离、先手测再调度、最小权限和结果复核。

#### GitHub Copilot Memory：证据、验证、作用域和过期

GitHub Copilot Memory 的公开预览文档提供了目前非常具体的产品化治理样本：

- 仓库事实与个人偏好分开存储和授权。
- 仓库事实携带指向代码的 citations，使用前回到当前分支验证，只有仍成立的事实才注入。
- 仓库事实只能在同一仓库使用；个人偏好只属于创建它的用户。
- 仓库拥有者或用户可以查看、删除相应记忆。
- 长期未使用的事实或偏好 28 天后自动删除；成功验证并使用时可刷新计时。

对 wyj-code 的含义：当前 `MemoryStore` 的“按类型写 Markdown + 全量拼接 8KB”不足以支持可信自进化，需要补充来源引用、当前分支验证、作用域、最后验证时间、过期/失效、查看/删除和选择性检索。

官方资料：[GitHub Copilot Memory](https://docs.github.com/en/copilot/concepts/agents/copilot-memory)。

### 3.2 研究侧实践

| 工作 | 可复用结论 | 对 wyj-code 的约束 |
|---|---|---|
| [Reflexion](https://arxiv.org/abs/2303.11366) | 从环境或外部反馈生成语言反思，保存在 episodic memory，而非更新模型权重 | 反思必须绑定任务反馈，不能只保存模型自我评价 |
| [Self-Refine](https://arxiv.org/abs/2303.17651) | 生成、反馈、再生成的测试时迭代可改善单次输出 | 适合候选改进生成，不足以单独证明改进有效 |
| [Agent Workflow Memory](https://arxiv.org/abs/2409.07429) | 从轨迹归纳可复用 workflow，并只在相关任务选择性提供 | 不应把所有历史经验常驻注入；需要工作流级检索和适用条件 |
| [Voyager](https://arxiv.org/abs/2305.16291) | 可执行 Skill 库、环境反馈、执行错误和自验证共同支持持续能力积累 | Skill 候选应可解释、可组合，并用实际执行结果验证 |
| [A Self-Improving Coding Agent（SICA）](https://arxiv.org/abs/2504.15228) | Agent 可以修改自身代码，并通过 SWE-bench Verified 等 benchmark 从 17% 提升到 53% | 自改代码必须在隔离分支/工作树和固定 benchmark 上比较，不能直接改主线 |
| [Darwin Gödel Machine](https://arxiv.org/abs/2505.22954) | 保存多版本 Agent 档案，开放式探索不同修改路径，用 benchmark 经验验证并保留高质量候选 | 需要候选归档、父子血缘、对照评测、资源预算、sandbox、人类监督和回滚 |

### 3.3 调研归纳的十条原则

1. **外部结果高于模型自评**：用户明确反馈、测试、CI、Review、benchmark 和真实运行结果优先；“模型认为自己做得好”不能单独晋级经验。
2. **先观察，再提议，再验证，再激活**：四个阶段必须分开落盘，任何失败都不能污染 active runtime。
3. **规则、记忆、工作流、代码分层**：事实进入 memory，强约束进入仓库说明或 Hook，重复流程进入 Skill，核心实现改动进入隔离实验。
4. **每条知识都有证据与作用域**：记录来源 session/turn/tool/test/commit/path、用户或项目作用域、适用条件与反例。
5. **使用前重新验证**：依赖代码的事实必须检查引用文件/行、内容摘要或 Git 对象是否仍成立。
6. **选择性检索且有 token 预算**：按任务、目录、语言、错误签名和工具相关性检索，禁止把全部历史塞进 system prompt。
7. **冲突、衰减和遗忘是一等能力**：支持 supersede、contradiction、TTL、stale、reject、forget 和 rollback。
8. **外部上下文默认隔离**：Web/MCP/仓库文档可能含 prompt injection；未经用户确认不得沉淀成个人偏好或高权限规则。
9. **真实能力晋级必须通过隔离评测**：Skill/Prompt/配置/核心代码改动最终应使用 managed worktree、固定任务集、基线对照、成本与回归门禁；v1.5.5 的结构化 Skill eval 只用于候选审查，不等价于已执行该门禁。
10. **本地、透明、可关闭**：延续 wyj-code 零遥测，提供 use/generate/auto-promote 分离控制、审计日志、导出和彻底删除。

| 现有基础 | 已有能力 | 距离自进化闭环的主要缺口 |

## 6. 最终架构

### 6.1 结构化 Episode 与证据

新增本地 append-only episode store，候选路径：

```text
~/.wyj-code/evolution/<project-id>/
  episodes/*.jsonl
  experiences/*.json
  candidates/memories/*.json
  candidates/rules/*.json
  candidates/skills/<candidate-id>/SKILL.md
  experiments/<experiment-id>/report.json
  active/index.json
  audit.jsonl
```

每个 episode 至少记录：

- session/turn/task id、cwd、Git root/branch/HEAD、输入目标摘要。
- 模型/Profile、模式、已附加工具快照摘要。
- 工具调用、错误签名、耗时、token、文件 diff 摘要。
- 执行过的测试/检查、exit code、Review finding、用户批准/拒绝/纠正。
- 最终状态：成功、部分成功、失败、取消、未知。
- 敏感信息脱敏状态与外部上下文来源标记。

第 2 轮已确认：一个 Episode 对应“一项用户目标从提交到成功、失败、取消或未知结果”的完整生命周期；turn、tool、test、review 作为 Episode 内部子事件，Session 只负责把多个 Episode 分组。Evolution store 不复制完整聊天正文和完整工具输出，只保存结构化摘要、错误签名、diff/test 元数据、必要的脱敏证据片段，以及指向原 Session/trace 的稳定引用。

主会话与子 Agent 应使用同一事件 schema；现有 SubAgent trace 可以迁移/适配为来源，而不是平行维护两套不可关联的数据。

### 6.2 结果判定优先级

候选默认优先级：

1. 用户明确的接受、拒绝、纠正和再次返工要求。
2. 确定性测试、编译、lint、CI、benchmark、真实 smoke test。
3. 项目 Review 与差异审计结果。
4. 工具 exit code、文件变化与任务完成条件。
5. 独立 reviewer/reflection 模型判断。
6. 执行模型的自评，只能作为最低权重辅助信号。

状态为 `unknown` 的 episode 不得自动生成 active 规则。

Episode 使用确定性状态机，不使用一个模糊总分跨越硬门禁：

- `verified_success`：完成条件和所有必要测试通过，且没有用户拒绝。
- `accepted_success`：用户明确接受但缺少完整测试；只能支持个人偏好，不能自动提炼仓库工作流。
- `partial`：仅完成部分目标或仍需返工。
- `failed`：必要测试失败、用户明确拒绝或出现安全问题。
- `cancelled`：用户取消、Esc 中断或进程退出；不计成功或失败。
- `unknown`：证据不足；不能自动晋级。

数值 confidence 只用于候选排序，不能覆盖上述硬状态。

### 6.3 Experience 与候选晋级状态机

候选状态：

```text
observed -> proposed -> validating -> validated -> active
               |            |            |          |
               v            v            v          v
            rejected      failed       stale     rolled_back
```

每次状态变化写入 audit log，保存操作者、原因、证据摘要和前一版本。Active 变更只在下一 Agent 安全边界进入新 snapshot，当前回合保持不可变，复用现有 Extensions/MCP runtime 的边界哲学。

### 6.4 证据化 Memory v2

建议把现有四类 Markdown 记忆迁移为兼容读取、结构化写入：

- `kind`：user preference / repository fact / failure pattern / workflow hint / reference。
- `scope`：user-global / repository / directory / language / tool / profile。
- `evidence`：session、turn、用户原话、commit/path/content digest、test/review 结果。
- `confidence`：由证据类型决定，不由模型任意填写。
- `valid_from`、`last_validated_at`、`expires_at`、`use_count`。
- `contradicts`、`supersedes`、`status`。
- `external_context` 与 `trusted_source` 标记。

仓库 citation 同时保存稳定身份与展示位置：repository identity、commit SHA、branch、仓库相对路径、committed 文件 Git blob OID、脏工作树 SHA-256、symbol 名称、上下文 fingerprint；行号只用于展示。检索前如 digest 改变，必须重新读取目标 symbol/片段验证。

Memory 冲突优先级固定为：当前用户明确指令 > pinned 用户偏好 > 更窄 scope > 当前分支重新验证的仓库事实 > 更高证据等级 > 同等级下较新记录。无法确定胜者时冲突项都不注入，进入人工处理。

检索只返回与当前任务相关、仍通过验证且在 token 预算内的条目。必须执行的规则继续放在 `CLAUDE.md`/兼容指令文件或 Hook，不依赖 Memory 命中。

第 2 轮已确认的自动晋级阈值：

- 用户偏好：用户明确表达一次即可激活，必须保存脱敏原话引用；隐式推断不能自动成为全局偏好。
- 仓库事实：当前分支代码 citation 与内容验证通过一次即可激活。
- 工作流经验：至少两个独立成功 Episode，且不能都来自同一次失败重试链。
- 失败模式：至少三次同类失败；确定性安全、凭证泄漏或数据损坏失败可一次晋级为高优先级候选。
- 任一候选存在相反用户反馈、测试失败或当前代码验证失败时，不得自动激活。

### 6.5 Rule 与 Skill 候选

Rule candidate：

- 只生成最小 diff 建议，不直接写入 `CLAUDE.md`、配置或 Hook。
- 显示产生原因、重复次数、正反例、影响目录和预计收益。
- 用户接受后才通过正常写工具落盘，并进入 Git diff/Review。

Skill candidate：

- 自动发现要求至少三个相似成功 Episode，且跨至少两个独立 Session；用户可通过 `/evolve skillize` 从一次成功任务显式发起候选生成。
- 生成 `SKILL.md`、references/scripts（如确有必要）、触发描述和边界。
- 自动构造至少 8 个 eval：2 个直接触发、2 个间接表达、1 个信息不全应追问、2 个不应触发、1 个安全边界。
- v1.5.5 将这些 eval 作为结构化审查用例，执行 frontmatter/内容结构检查，并记录历史成功 Episode 数与独立 Session 数；当前实现不调用 Agent 逐例 replay，也不比较安装前后成功率、步骤数、token、耗时或回归。完整隔离执行与 baseline/candidate 对照属于后续评测执行器。
- 默认人工批准后安装到项目或用户 scope；安装仍复用 Extensions lockfile、原子写入与回滚。
- 批准前必须展示来源、证据、candidate diff、eval、作用域和风险；批准时先创建保护 checkpoint。
- 当前回合继续使用旧 snapshot，下一安全边界才激活；写入、配置或 lockfile 任一步失败都恢复此前状态。

### 6.6 v1.6.0 核心代码自修改实验预留

L4 已明确不进入 v1.5.5。为避免 v1.5.5 的 Episode、Experience 和 Experiment schema 阻塞后续升级，本版只冻结以下兼容边界，不实现自动自改代码：

- 只能在 managed worktree 中创建 candidate，不得直接修改当前工作树或 `master`。
- 从固定 baseline commit 创建父候选；保存 parent/child、变更动机、模型、预算和 patch digest。
- 运行固定 benchmark + workspace 全量门禁 + 安全扫描 + 真实 smoke test。
- 与 baseline 进行成对比较；质量提升但成本、稳定性或安全回退的候选不得晋级。
- 不自动 commit/push/tag/release；必须人工 Review 与显式接受。
- 保留失败候选和结果摘要以避免重复探索，但对上下文做限额和过期。

### 6.9 保留、容量与 Memory v1 迁移

- 仓库事实 28 天未成功验证后转为 stale；重新验证并使用后刷新。
- 工作流经验 60 天未使用后转为 stale。
- 用户明确偏好不自动删除，180 天未使用后进入待复核状态。
- 失败 Episode 保留 30 天，未处理候选保留 90 天，audit 保留 180 天。
- 每项目默认上限 100 MB；只按 LRU 清理非 active、非 pinned 内容。
- 继续兼容读取现有 `~/.wyj-code/memory`，启动时不得静默改写。
- `/evolve migrate --preview` 先展示迁移计划；确认后使用原子写入并保留旧目录备份。
- 至少一个 minor 版本内支持回滚；未获得用户明确授权不得自动删除旧 Memory 文件。
- Evolution store 默认只保存摘要、错误签名、diff/test 元数据和必要脱敏证据；完整正文与完整工具输出继续留在原 Session/trace。
- Web/MCP/ToolSearch Episode 默认排除；用户可用 `/evolve include <episode>` 预览并手动纳入仓库候选。外部结论必须由当前代码、测试或用户明确陈述独立验证，且永远不能直接生成用户全局偏好。

## 7. 安全与非干扰门禁

- 默认本地存储、零遥测；不上传 episode、memory、Skill 候选或 diff。
- 外部 Web/MCP/ToolSearch 内容默认不得生成用户级偏好；仓库文本也只能形成低信任候选。
- 所有持久化前复用并扩展 `redact_sensitive_text`；导出再次脱敏。
- 候选脚本、Hook、Skill 与核心代码实验必须经过现有 PermissionPolicy 和 SandboxRunner。
- 当前回合 runtime snapshot 不受后台进化任务改变；只在下一安全边界应用已批准内容。
- 任何写入仓库的建议都进入普通 Git diff，不绕过用户未提交修改，不自动清理失败现场。
- 不读取、改写或训练于未获授权的其它项目、历史目录或外部账户数据。
- 不用一次成功覆盖明确用户偏好；不把一次失败永久固化为禁止规则。
- 所有候选可查看证据、拒绝、遗忘、回滚；拒绝原因可用于避免重复提议，但不得被解释为新的广泛规则。

## 8. 深度访谈决策

### 8.1 第 1 轮已确认

1. **首要目标**：优先让 wyj-code 越来越理解用户偏好与当前仓库，减少重复解释和重复犯错。
2. **自动化上限**：充分证据支持的普通 Memory 可自动激活；Rule、Hook、Skill 必须人工批准。
3. **成功判定**：测试/CI/Review 等硬证据与用户未要求返工或明确接受共同判断，模型自评不能覆盖外部失败。
4. **作用域**：仓库事实限制在同一仓库；个人偏好独立全局保存；Web/MCP 默认隔离，不直接进入进化。
5. **版本边界**：v1.5.5 交付 TUI + L0-L2 + L3 candidate/eval；L4 自改核心代码进入 v1.6.0。
6. **默认开关**：经验使用和生成默认开启；自动晋级 Rule/Skill 默认关闭；外部上下文默认不参与提取。

### 8.2 第 2 轮已确认

1. **Episode**：以一项完整用户目标为单位，turn/tool/test 为子事件；不重复保存完整正文与工具输出。
2. **反馈**：无打扰地推断返工/纠正/接受，同时提供 `/evolve feedback good|bad` 和候选 accept/reject；显式反馈优先。
3. **Memory 阈值**：用户偏好一次明确表达；仓库事实一次当前分支验证；工作流两个独立成功 Episode；普通失败三次，确定性安全/数据损坏失败一次进入高优先级候选。
4. **Skill 阈值**：三个相似成功 Episode、跨两个 Session 自动生成；允许用户从一次成功任务手动 `skillize`。
5. **Skill eval**：至少 8 例，覆盖直接/间接/信息不全/不应触发/安全边界；v1.5.5 先交付结构化用例、结构检查和历史证据，成功率/步骤/token/耗时/回归对照待隔离 replay 执行器补齐。
6. **后台与预算**：任务结束空闲 5 分钟、单 worker、独立 Profile、每日 50,000 token 与 30 分钟；不足时跳过。
7. **保留与容量**：分类 TTL/复核周期；每项目 100 MB；active/pinned 不自动清理。
8. **UI**：`/evolve` 管理中心 + CLI/JSON；只对高置信度待审批候选提示一次。
9. **迁移**：旧 Memory 兼容读取；preview 后原子迁移并保留备份，至少一个 minor 版本内可回滚。
10. **隐私**：Evolution store 保存结构化摘要和必要脱敏证据，不复制完整 Session/trace。

### 8.3 第 3 轮已确认

1. **结果状态**：确定性状态机；confidence 只排序，不覆盖硬门禁。
2. **冲突**：当前明确指令、pinned、窄 scope、当前分支验证、证据等级、更新时间依次优先；无法裁决则不注入。
3. **Citation**：Git blob/工作树 digest/symbol/context fingerprint 为稳定标识，行号只展示；变化后重新验证。
4. **外部上下文**：默认排除；允许 preview 后手动纳入仓库候选，必须由本地事实独立验证，不生成全局偏好。
5. **后台失败**：三次可恢复重试与退避；Auth/InvalidRequest/权限/安全错误不重试；doctor 标红但不影响前台。
6. **批准事务**：展示证据、diff、eval、scope、风险；保护 checkpoint；原子安装；下一边界应用；全状态回滚。
7. **交互**：`Active / Candidates / Episodes / Health` 四视图与完整 CLI/JSON；危险动作二次确认。
8. **实施授权**：访谈结束后立即实现完整本地 v1.5.5 release candidate；不 commit、push、tag 或发布 Release。
