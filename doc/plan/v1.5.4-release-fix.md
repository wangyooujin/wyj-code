## 1. 背景与根因

v1.5.3 已完整发布 P1/P2、国内模型多工具调用兼容、ToolSearch 核心执行面和五平台 checksum 门禁。发布后复核 computer-use 权限链路时发现：`Tool::needs_permission` 已按 action 把截图、窗口枚举和元素检查定义为只读，但执行器更早调用的 `PermissionPolicy` 仍把 `computer` / `app_computer` 整类视为副作用工具。

结果是在无交互审批通道的 headless、daemon 或类似表面中，安全的只读观察会在到达工具自身权限判断前被错误拒绝。该缺口不影响变更操作的失败关闭，但会削弱自动化、ACP/daemon 和国内模型 computer-use 的可用性。

## 2. 实现范围

- `PermissionPolicy` 的副作用判断同时接收工具名与原始 input，按 action 与工具自身权限语义对齐。
- `computer` 只读动作：`screenshot`、`zoom`、`cursor_position`、`wait`。
- `app_computer` 只读动作：`list_windows`、`screenshot`、`inspect_element`。
- 点击、拖拽、按键、输入、滚动，以及未知或缺失 action 继续视为有副作用。
- 交互表面的变更动作继续返回逐调用审批；无 UI 表面继续拒绝。
- 不改变工具注册、ToolSearch schema、Plan/Allowlist、写路径、网络域名、sandbox、foreground compatibility 或项目级授权范围。

## 3. 回归测试

- headless Prompt：变更、未知和缺失 action 必须 Deny。
- TUI interactive Prompt：只读 action 直接 Allow，变更 action 必须 Ask。
- workspace 全量测试、check、fmt、strict Clippy、Node/YAML、metadata 与 diff 门禁全部通过。
