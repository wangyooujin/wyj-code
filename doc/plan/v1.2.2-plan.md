# wyj-code v1.2.2 计划与实施记录

## 目标

统一解决 Skill、MCP、Plugin 的发现、迁移、安装、升级、启停、诊断和运行时接入，优先服务个人日常开发，同时保持旧 `~/.wyj-code`、`.wyj`、`.claude` 路径兼容。

## 已实施的基础能力

- `installed.json` 升级到 lockfile v2，新增跨类型 `extensions` 索引并兼容旧字段。
- 新增 `wyj-store::extensions`：统一资源列表、健康/冲突诊断、原生 `.mcp.json` 与 `~/.claude.json` MCP 迁移。
- 新增 `wyj-code extensions list|doctor|migrate|install|upgrade|enable|disable|remove`，支持 `--json` 和作用域。
- Skill/Claude command 递归加载子目录并映射为 `namespace:name`。
- MCP 配置支持 stdio 与 Streamable HTTP，支持 URL 和 `${ENV_VAR}` header 引用。
- MCP 工具采用 `mcp__server__tool` 稳定命名，旧安装流程继续可用。
- `/extensions` 作为 TUI/headless 统一诊断入口，`/mcp`、`/skills`、`/plugins` 保留兼容。
- 安装/卸载/启停文案改为“下一次 Agent 回合边界应用”，避免继续承诺必须重启。
- 新增 `wyj-mcp::McpRuntime`：按 server 配置指纹管理连接，异步连接结果在安全边界
  原子替换主 Agent、子 Agent 工厂和 `/model` 重建所共享的工具快照；禁用、卸载或升级
  后旧 MCP 工具不会继续留在下一回合。
- `/extensions` 已成为真正的 TUI 列表/详情/操作面板：支持键盘浏览、详情滚动、启用、
  禁用、卸载、刷新；headless 继续输出 JSON，旧的三个专用面板和 slash alias 保留。
- Plugin Agent 定义改为可刷新共享快照；启用/禁用插件后下一回合更新 `Agent` 工具的
  `subagent_type` 描述和实际可创建类型。
- Plugin dependencies 支持递归安装、配置的跨 marketplace 依赖、循环检测和 semver
  约束；Skill marketplace commit、Plugin source commit、MCP 包描述 digest 写入 v2 索引。
- lockfile、主配置和项目 MCP 配置使用同目录临时文件 + rename 原子替换；Skill/MCP
  安装在 lockfile 持久化失败时回滚资源文件或配置。

## 已明确保留的边界

- Plugin 物化目录的全量 staging/backup 事务、每个资源的持久化 trust decision、以及
  安装前自动预取外部运行时依赖，仍作为后续安全增强；v1.2.2 不会静默执行 npm/pip 安装。
- MCP 连接采用 lazy/background 策略：配置变化会在下一安全边界被观察，连接握手异步完成；
  握手未完成前当前回合不强行阻塞，连接成功后从后续回合可见。
- hooks/themes 不在 v1.2.2 范围内。
