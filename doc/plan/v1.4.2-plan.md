# wyj-code v1.4.2 计划与实施记录

> 状态：**已实施，纳入 v1.4.2**（基线为已公开的 `v1.4.1`；本版本合并其后尚未提交的 TUI 键盘焦点导航，以及 Codex 风格静态执行流重构。无配置迁移，不改变 Agent/API/工具执行协议）。

## 1. 背景与版本边界

`v1.4.1` 已在提交 `fb7ee03` 上发布，之后工作树保留了 4 个尚未提交的 TUI 文件：

- `crates/tui/src/app.rs`
- `crates/tui/src/render.rs`
- `crates/i18n/locales/zh.yml`
- `crates/i18n/locales/en.yml`

这些改动先稳定了输入框历史导航，并补全 Task List 与 SubAgent 的详情浏览，随后进一步把聊天区从“选中某条消息再展开详情”重构为 Codex 风格的静态执行流。已经公开的 `v1.4.1` 标签不移动，以上内容作为新的补丁版本 `v1.4.2` 发布。

## 2. 目标

1. 普通 `↑/↓` 始终服务输入框和输入历史。
2. Task List 与 SubAgent 保留键盘选择和独立详情能力，聊天区不再依赖单消息选中/展开。
3. Thinking 和工具执行结果默认紧凑展示，长输出不会淹没当前执行流。
4. Edit/Write 无需手动展开即可直接看到有颜色区分的代码 diff。
5. 默认持续跟随最新内容；用户阅读历史时，新消息不得抢走视口。

## 3. 交互定义

### 3.1 Composer 与内容焦点

- 普通 `↑/↓`：单行输入浏览历史；多行输入先移动逻辑行，到首行/末行后才进入历史。
- 内容焦点中的 `↑/↓`：在聊天视觉行、Todo 条目和 SubAgent 条目间连续导航。
- `Enter/Space`：仅用于 Todo/SubAgent 详情；聊天区不再执行展开。
- `Esc`：按“详情 → 列表 → Composer”逐级返回，未发送草稿和附件保持不变。
- `Command+↑/↓`：跳到当前会话顶部/底部。

### 3.2 静态执行流

- 删除聊天消息的选择背景、`▶` 标记、展开/折叠状态、详情滚动状态和 `Ctrl+O`。
- Thinking、ToolResult、BashOutput 的标题不计入预览额度，正文最多展示 3 个终端视觉行。
- 逻辑长行先按当前终端宽度换行，再按视觉行计数；超出时额外显示一行 ASCII `...`。
- 用户输入和 AI 最终回答保持完整展示，长单行自然换行，不应用三行上限。
- ToolCall 与相邻 ToolResult 继续按 `sequence_no` 合并为紧凑执行块。

示例：

```text
  ⏺ Read(crates/tui/src/render.rs)
    ⎿ 第一行
       第二行
       第三行
       ...
```

### 3.3 Edit/Write diff

- Edit/Write 成功结果跳过“已替换/已写入”状态首行，从真实 diff 开始展示。
- `- ` 删除行使用错误/红色样式，`+ ` 新增行使用绿色，上下文使用灰色。
- diff 同样最多 3 个终端视觉行，超出显示 `...`。
- 会话恢复时按 `tool_use_id` 同时重建工具序号和工具名，确保历史 Edit/Write 仍能识别为 diff。

### 3.4 尾部跟随

- TUI 启动时显式关闭鼠标捕获，终端文字可直接拖选复制，不要求 Shift/Option；应用内历史使用 PageUp/PageDown 等键盘入口浏览。
- 初始状态、用户提交新消息、进入 Todo 详情或跳到会话末尾时跟随内容最后一行。
- 用户主动向上滚动后关闭尾部跟随，保留 `chat_scroll` 阅读位置。
- 上滚期间到达的消息、流式 TextDelta/ThinkingDelta 和工具结果只设置“下方有新消息”提示，不修改当前滚动位置。
- 用户滚回最大偏移后恢复尾部跟随并清除新消息提示。

## 4. 实现范围

### `crates/tui/src/app.rs`

- 引入并收口 `UiFocus::Composer/Chat/Todos/TodoDetail/SubAgents` 的显式焦点状态机。
- 删除 `selected_message_id`、选择锚点、最后展开消息和消息详情滚动等聊天选择状态。
- Chat 焦点中的 `↑/↓` 改为逐视觉行滚动，并在底部自然跨到 Todo/SubAgent。
- 新增统一的新聊天内容通知逻辑，覆盖消息插入与流式 delta。
- 保留 Todo/SubAgent 的 `selected_*`、`*_detail_open`、`*_detail_scroll` list/detail 状态。

### `crates/tui/src/render.rs`

- 使用统一的三视觉行预览器渲染 Thinking、ToolResult 和 BashOutput。
- 删除聊天消息选中样式、展开提示、详情 viewport 与 `Ctrl+O` 文案。
- Edit/Write 结果自动提取并着色 diff。
- 用户输入和错误回答改为宽度内自然换行，避免截断丢失内容。
- `draw_chat` 只处理尾部跟随或滚动位置 clamp，不再定位选中消息。

### i18n 与开发文档

- 更新中英文 `/help` 和输入框快捷键提示。
- 更新根 `CLAUDE.md` 与 `crates/tui/CLAUDE.md`，移除已经失效的聊天消息展开架构说明。

## 5. 兼容性与非目标

- 不新增配置项，不改变配置文件格式、Session/API 消息结构或工具协议。
- 不恢复终端原生 scrollback；当前 Fullscreen + 应用内滚动架构保持不变。
- 不删除 Todo、SubAgent、Agents Catalog 等真正的列表选择和独立详情交互。
- `v1.4.1` 标签和 Release 保持不可变，所有后续 TUI 改动只进入 `v1.4.2`。

发布前必须全部通过：

```bash

git diff --check
cargo test -p wyj-tui --locked
cargo test --workspace --locked -q
cargo clippy --workspace --all-targets --locked -- -D warnings
node --check site/script.js
cargo metadata --no-deps --format-version=1
```

- `cargo test -p wyj-tui --locked`：132 passed，0 failed。
- `cargo test --workspace --locked -q`：531 passed，0 failed。
- `cargo clippy --workspace --all-targets --locked -- -D warnings`：通过，0 warnings。
- `cargo fmt --all -- --check`、`git diff --check`、`node --check site/script.js`：全部通过。
- `cargo metadata --no-deps --format-version=1`：11 个 workspace package 均为 `1.4.2`。

重点测试覆盖：

- 普通方向键始终属于输入框和输入历史。
- Chat 逐视觉行滚动以及 Chat → Todo → SubAgent 边界导航。
- Todo 单任务详情的进入、逐行滚动与 Esc 返回。
- Thinking/普通工具结果/长单行工具结果最多 3 个视觉行并显示 `...`。
- Edit/Write diff 文本、配色与长 diff 截断。
- 用户输入和 AI 最终回答不受三行限制。
- 上滚期间新消息与流式 token 不改变阅读位置，回到底部后恢复跟随。
- 历史并行工具调用按 `tool_use_id` 恢复正确序号和工具名。
