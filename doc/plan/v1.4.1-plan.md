# wyj-code v1.4.1 计划与实施记录

> 状态：**已实施，纳入 v1.4.1**（基线为 `v1.4.0`；本版本聚焦 TUI 剪贴板/附件输入可靠性，以及旧版 foreground `computer` 的多窗口与连续动作稳定性，不新增配置项，不改变 v1.4 默认后台优先、前台接管默认关闭的安全架构）。

## 一、版本目标

v1.4.1 是 v1.4.0 的补丁版本，解决两组已经在真实使用中暴露的问题：

1. 终端只会为文本产生 bracketed-paste 事件，纯图片剪贴板按 Ctrl/Command+V 时 TUI 可能完全收不到图片；附件又使用独立面板展示，既占空间，也存在只附图片但无法直接 Enter 提交、ESC/Ctrl+C 清理语义不统一等边界。
2. 旧版 foreground `computer` 在 macOS 同一前台 App 存在多个窗口时可能选错“当前窗口”，且每次动作会消费截图观察，导致“点击输入框 → 输入文字”这类最基础的连续动作被规律性误报为 `target_changed`。

本版本的完成标准是：粘贴入口、附件展示与提交/清空语义收敛成一套；foreground `computer` 只有在前台窗口真的改变时才拦截连续动作，同时不削弱 v1.4 已建立的人类优先与 fail-closed 边界。

## 二、TUI 剪贴板与附件输入

### 2.1 主动读取系统剪贴板

- 新增统一的 `ClipboardPaste::{Image, Text}` 表示，以及 `read_system_clipboard()` / `apply_clipboard_paste()` 处理链。
- `Event::Paste` 继续负责终端 bracketed-paste 文本；Ctrl/Command+V 键位会主动读取系统剪贴板，从而覆盖纯图片不会触发 `Event::Paste` 的终端限制。
- 图片 flavor 优先于文本 flavor；RGBA 图片在内存中编码为 PNG/base64 后进入待发送附件，不落临时文件。
- 单行文字直接进入输入框；多行文字保留短暂粘贴数量提示；可解析的文件路径继续转成文件附件。
- 相同图片内容或相同文件路径只附加一次，避免终端同时发出键位事件与 paste 事件时产生重复附件。

### 2.2 输入框内联附件占位

- 图片和文件在输入框开头显示持久的 `[Image]` / `[File: name]` 占位符，多个附件紧凑排列。
- 占位符通过克隆后的展示用 `InputBox` 投影，不写入真实输入文本，因此不会混入发送给模型的正文或输入历史。
- 删除独立附件预览条，输入区高度只由“正文 + 占位符”的实际折行结果决定，减少 TUI 底部空间占用。
- 光标位置与折行继续复用 `InputBox` 的同一套计算，附件前缀不会造成可见光标与真实编辑位置错位。

### 2.3 统一提交、清空与面板借用语义

- 输入组合器的“有内容”统一定义为：文字非空或待发送附件非空；支持只粘贴图片/文件后直接 Enter 发送。
- ESC 与 Ctrl+C 的首次清空会同时移除文字、附件、粘贴提示、补全列表和历史草稿状态，不再留下不可见附件。
- Agent 忙碌时的排队消息同样支持 attachment-only 输入。
- `/mcp`、`/skills`、`/plugins`、`/schedule` 等借用主输入框的配置编辑态会优先接收粘贴文字，不让 `Event::Paste` 穿透到聊天附件逻辑；显式 Ctrl/Command+V 也不会再被当成字面量 `v`。

### 2.4 覆盖测试

- Ctrl/Super+V 键位识别。
- 单行与多行文字粘贴提示差异。
- 图片附件创建与重复内容去重。
- 文字与附件统一清空。
- attachment-only 组合器可提交。
- 单个与多个图片占位符渲染，且不修改真实输入文本。

## 三、foreground `computer` 稳定性修复

### 3.1 多窗口前台识别根因

macOS 的 `xcap::Window::is_focused()` 本质上按 `NSWorkspace.activeApplication().pid` 判断，因此同一个前台 App 的多个可见窗口都可能返回 `true`。旧实现从 `list_windows()` 中查找第一个 focused 窗口，但 `list_windows()` 为展示稳定性又按 focused/app 名/window id 重排，最终选中的是“同 App 中排序靠前的窗口”，而不一定是真正位于最前面的窗口。

当交易软件、浏览器或 IDE 弹出/关闭浮窗时，这个任意候选会变化，即使用户实际操作目标从未切换，也会触发 `target_changed`。

### 3.2 保留 z-order 的唯一前台窗口

- 将窗口收集拆为 `collect_targets_in_z_order()`，保留 `Window::all()` 的系统原始顺序。
- `list_windows()` 仍按原规则重排，保证面向用户的窗口列表稳定。
- 新增 `frontmost_window()`，直接从 z-order 中取第一个 focused 窗口，供 foreground `computer` 做身份复核。
- Windows 的 focused 判断本就基于 `GetForegroundWindow() == hwnd`，最多只有一个候选，因此该修复不改变 Windows 语义。

### 3.3 截图观察跨连续动作复用

- `validate_foreground_observation()` 从消费式 `.take()` 改为保留式 `.clone()`。
- 每个变更动作前仍重新读取真正的前台窗口，并核对 `window_id`、`pid` 与 `generation`；只有身份确实改变才返回 `target_changed`。
- 截图观察可覆盖“点击 → 输入 → 按键”等连续动作，直到重新截图覆盖、前台目标改变，或达到现有约 20 次无截图动作上限。
- 人类输入抢占、Input Monitoring 不可用、锁屏、前台接管未批准等 v1.4 安全门禁完全保留。

### 3.4 模型侧防误判指引

- 全屏缩略图中的小字、配置、错误码与诊断文字不得作为事实直接报告，必须由工具结果或 zoom 裁剪确认；仍不可读时应明确说明，而不是补全“看起来合理”的内容。
- `app_computer` 返回某个元素不支持 AXPress 时，按固定的控件能力缺失处理，不自动重复同一点击。
- 用户明确允许切换到旧 `computer` 后，模型仍需先确认/重新激活目标 App；该工具不绑定窗口，所有动作只作用于当时真正最前台的窗口。

## 四、兼容性与边界

- 无配置格式、存储格式、CLI 参数或 MCP/Skill/Plugin 兼容性变化。
- `app_computer` + `window_capture` 仍是默认路径；foreground `computer` 仍是显式开启的兼容模式，不新增任何自动回退。
- Linux 继续使用 computer-use 平台桩实现；TUI 文本粘贴逻辑可编译运行，系统图片剪贴板能力取决于 `arboard` 所支持的桌面环境。
- 本版本不新增图片预览渲染；终端内只显示 `[Image]` 占位符，实际图片仍以模型可消费的 image content block 发送。

## 五、关键改动文件

- `crates/tui/src/app.rs`：系统剪贴板读取、统一 paste 处理、组合器提交/清空语义与测试。
- `crates/tui/src/render.rs`：输入框附件占位投影、布局收敛与渲染测试。
- `crates/computer/src/target.rs`：z-order 窗口收集与 `frontmost_window()`。
- `crates/tools/src/computer.rs`：真实前台窗口复核与可复用截图观察。
- `crates/core/src/prompts.rs`、`crates/tools/src/descriptions.rs`：computer-use 防误读、防盲重试与前台目标提醒。

## 六、发布门禁

发布 `v1.4.1` 前必须全部通过：

```bash
git diff --check
cargo fmt --all -- --check
cargo test --workspace --locked -q
cargo clippy --workspace --all-targets --locked -- -D warnings
node --check site/script.js
cargo metadata --no-deps --format-version=1
```

2026-07-27 本地发布前验证结果：`cargo check --workspace` 通过；workspace 共 522 个测试通过、0 失败；全 workspace/all-targets clippy 在 `-D warnings` 下通过；Rust 格式、diff whitespace、官网 JavaScript 语法与 `1.4.1` 版本解析均通过。

标签 `v1.4.1` 必须与 workspace package version `1.4.1` 一致。推送标签后由 `.github/workflows/release.yml` 完成 Linux/macOS/Windows 五个 target 的构建、归档、单包 sha256 与聚合 `SHA256SUMS`，最终以公开 Release 页面和资产可达性作为发布完成证据。
