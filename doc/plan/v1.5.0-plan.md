## 1. 版本决策

v1.4.4 已经公开发布。完整 P2 包含 Workflow runtime、自动 Git worktree、ACP daemon、跨连接 session registry、Plugin runtime 和 LSP 查询，属于新增用户可见能力，不适合覆盖既有 patch tag，也不应继续使用 patch 版本号。

因此本次交付版本为 **v1.5.0**：

- 不移动、不删除、不重签 `v1.4.4`。
- 将此前保留在工作树中的 TUI/Markdown/超链接修改与完整 P2 一次性整合。
- 根 workspace、全部 `wyj-*` crate、Cargo.lock、README、CHANGELOG、站点和发布说明统一使用 `1.5.0`。
- 创建新的 annotated tag `v1.5.0`，tag 必须解引用到最终发布提交。

## 2. 与 Claude Code 对齐的产品目标

本版本不追求复制专有实现，目标是把 Claude Code 级别的关键工程边界变成 wyj-code 的可验证本地能力：

1. 编码任务可隔离执行，变更必须经过显式 diff review 和选择性接受。
2. 多节点 Agent 工作流有可持久化状态、权限上限、预算和控制面。
3. 会话运行时与 TUI 解耦，可由 ACP/IDE 客户端连接、断线重连和继续控制。
4. Plugin 不只完成安装，还能安全地贡献运行时资源和真实 LSP symbol 查询。
5. 国内模型缺少稳定工具调用行为时，依靠严格 schema、可见 fallback、lazy tools、保守能力目录和失败关闭执行边界降低风险。
6. 所有公开材料区分静态协议兼容、fixture 验证和真实 live probe，不使用或复述已暴露的 Key。

## 4. Managed Worktree

实现位置：

- `crates/core/src/workspace.rs`
- `crates/cli/src/workspace_cmd.rs`
- `crates/cli/src/workflow_cmd.rs`

CLI：

```bash
wyj-code workspace create --base HEAD --purpose "isolated coding task"
wyj-code workspace list [--json]
wyj-code workspace diff <id> [--summary-only] [--json]
wyj-code workspace accept <id> <paths...> [--json]
wyj-code workspace dispose <id> [--force]
```

行为约束：

- manager-owned worktree 位于用户配置目录下，和父 checkout 分离。
- `diff` 必须覆盖 text/binary 统计，并列出 patch 中无法内联展示的路径。
- `accept` 只接受显式列出的仓库相对路径。
- 接受前校验 symlink 逃逸、父 checkout HEAD 前进、父文件并发修改、删除和 binary 内容，不能静默覆盖用户工作。
- 有未接受变更的 worktree 默认不能清理；丢弃必须显式 `--force`。

## 5. Workflow 自动隔离

实现位置：

- `crates/core/src/interfaces.rs`
- `crates/core/src/workflow.rs`
- `crates/cli/src/workflow_cmd.rs`

CLI：

```bash
wyj-code workflow validate workflow.json [--json]
wyj-code workflow run workflow.json [--json]
wyj-code workflow status <workflow-id> [--json]
wyj-code workflow control <workflow-id> pause|resume|approve|retry|skip|cancel
```

运行语义：

- Workflow 定义是数据，不允许节点携带任意框架代码。
- 每个节点有只能收紧的 allowed tools、write roots、allowed domains、require sandbox 权限上限。
- 支持 DAG 环检测、依赖状态、`max_parallel`、token budget、human approval、retry/skip/pause/resume/cancel。
- 状态和控制请求持久化，独立 CLI 进程可查看并向运行中的 workflow 排队发送控制。
- 拥有 Write/Edit/Bash 且配置非空 `write_roots` 的 Agent/Review 节点自动隔离；Index 和 HumanApproval 节点不创建 worktree。
- 启动 workflow 时先从当前工作树（包括未提交修改和未跟踪文件）创建 checkpoint commit，不修改用户真实 Git index。
- 每个编码节点从同一 checkpoint commit 创建独立 managed worktree，并在 worktree 根重新创建 CodeIndex。
- 节点 write roots 映射到 worktree，父 checkout 不作为写目标。
- 成功结果返回 workspace id/root、changed files、insertions/deletions，以及 review/accept 命令。
- 不自动接受或删除；节点失败时同样保留现场。

## 6. ACP 与 daemon

实现位置：

- `crates/core/src/session_runtime.rs`
- `crates/core/src/interfaces.rs`
- `crates/cli/src/acp.rs`

入口：

```bash
wyj-code acp
wyj-code daemon --listen 127.0.0.1:61337
```

协议与生命周期：

- `acp` 通过 stdin/stdout 提供连接级 adapter；连接结束时清理该连接创建的 session。
- `daemon` 使用进程级全局 session registry，所有 TCP 连接共享，不再按 connection 建独立 map。
- daemon 客户端断线不终止活动 session；新连接可用 `session/load` attach 活动或持久化 session。
- permission client 在重连后重新绑定当前连接。
- ACP initialize 声明 interface schema version 2、全局 daemon session 能力和扩展方法。

扩展方法：

```text
_wyj/session/list
_wyj/session/control
```

`_wyj/session/control` 覆盖：

- Submit
- Interrupt
- Rewind
- Branch
- Workflow control
- Close

Rewind/Branch 文件恢复必须先返回 preview；未确认不写文件，`confirmed=true` 后才执行，并先创建保护 checkpoint。Branch 创建新 session 并保留 parent session/checkpoint 血缘。

统一事件流覆盖：

- text/thinking delta
- tool started/finished
- usage/error/turn finished
- PermissionRequested
- DiffAvailable
- CheckpointChanged
- AgentStateChanged

## 7. CodeIndex 与 Plugin LSP

实现位置：

- `crates/core/src/code_index.rs`
- `crates/store/src/plugin_runtime.rs`

本地索引：

- 维护 lexical/symbol 索引并持久化 schema/version/fingerprint。
- 查询结果包含 path、line、kind、symbol/container 和来源。
- 索引损坏、过期或查询失败时使用 ignore-aware direct scan，不把搜索能力整体关闭。

Plugin LSP：

- LSP 进程由 supervisor 管理并在关闭时回收。
- 实现标准 `Content-Length` framing。
- 完成 initialize/initialized。
- 调用 `workspace/symbol`，解析 file URI、symbol kind、container、path 和 line。
- LSP 结果与本地索引合并、去重、排序和截断；真实 LSP 命中优先于同等本地结果。
- 启动、协议或查询失败保持 fail-soft，本地 lexical/direct-scan 继续可用。

## 8. Plugin Runtime 事务式激活

实现位置：`crates/store/src/plugin_runtime.rs`。

支持的 runtime contributions：

- hooks
- output styles
- themes
- channels
- LSP servers
- monitors
- settings schema
- userConfig

每个插件先在 staged catalog 中完整解析和验证；任一 contribution 无效，整插件不生效，不能留下部分 hook/theme/channel。不同插件名称冲突使用先到先得并记录 warning。settings schema 先编译，再用它验证 userConfig。

## 9. Review 与 CI

实现位置：

- `crates/cli/src/review_cmd.rs`
- `.github/workflows/review.yml`
- `.github/workflows/release.yml`

CLI：

```bash
wyj-code review run --base HEAD^ --head HEAD --json
wyj-code review run --base origin/master --head HEAD --output review.json --fail-on high
```

门禁：

- diff 读取禁用外部 diff driver。
- 解析 rename、带空格路径和 binary numstat。
- secret-like evidence 只保留脱敏证据，不把完整 token 输出到报告或日志。
- Review Action 与本地 CLI 使用同一实现。
- Release Action 强制运行：

```bash
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
```

- headless REPL 用户 `!command` 与 TUI 一样走统一 SandboxRunner；没有 UI 时不允许无隔离降级。

## 11. 国内模型专项边界

- vendor 与 wire protocol 继续分离，避免把“OpenAI-compatible”误当成同一家供应商。
- ToolSearch/lazy schema 降低国内模型在大工具集上的 schema token 和选错工具概率。
- 工具参数只能有限语法修复，之后必须通过原始 JSON Schema；缺少语义字段时回灌精确错误重试，不用空对象执行。
- fallback 只能在同角色、可恢复错误和完整消息边界发生，Auth/InvalidRequest/安全错误不触发逃逸。
- live probe 只读取独立 `WYJ_CODE_PROBE_API_KEY`，不扫描或复用 Profile Key。
- 此前暴露的 MiniMax Key 不读取、不使用、不复述、不写入、不测试。
- 没有独立轮换 Key 时，MiniMax 与其他国内模型保持 `static_only` / protocol-compatible，不宣称 live verified。

## 13. 远端发布门禁

1. 使用简体中文 commit message 提交全部改动并 push `master`。
2. 创建 annotated tag `v1.5.0` 并 push；不移动 `v1.4.4`。
3. 等待 Release 和 Pages Actions 完成。
4. 验证以下五个平台归档：
   - `x86_64-apple-darwin`
   - `aarch64-apple-darwin`
   - `x86_64-unknown-linux-musl`
   - `aarch64-unknown-linux-musl`
   - `x86_64-pc-windows-msvc`
5. 每个平台必须同时有 archive 和 sidecar checksum，并提供聚合 `SHA256SUMS`。
6. sidecar checksum 与 `SHA256SUMS` 对同一资产的 digest 必须一致。
7. GitHub Release 必须 `draft=false`、`prerelease=false`。
8. Pages 首页显示 v1.5.0，且保留 v1.4.4 历史卡片。
9. `master == origin/master`，`v1.5.0^{}` 指向发布提交，`v1.4.4^{}` 仍为 `fd28a8834eb80532d6b053964bfcecdc10587698`。

## 14. 不在本版本夸大的能力

- 自动 worktree 只覆盖 Workflow 中满足写权限条件的 Agent/Review 节点，不宣称所有 TUI/SubAgent 自动隔离。
- CodeIndex 是 lexical/symbol + plugin LSP `workspace/symbol`，不宣称 embedding/vector 语义索引。
- ACP daemon 默认是本地控制面，不自带公网多租户鉴权或云执行平台。
- Windows 没有与 macOS Seatbelt/Linux bubblewrap 同等级的原生 sandbox。
- 国内模型没有独立 live probe Key 时不宣称端到端真实验证。
