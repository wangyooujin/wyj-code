# wyj-code v1.0.1 计划

## Context

v1.0.0 已发布，功能面（26 命令 / 15 工具 / TUI / MCP·skills·plugins 三市场 / 子 Agent 编排 / 记忆 / 压缩 / i18n）已相当完整。对齐 Claude Code / Codex 的真实差距调研后确认：**最大硬伤是逐调用工具权限确认缺失**——Normal 模式下 Edit/Write/Bash 直接执行、零确认弹窗；UI 外壳（`draw_permission_dialog`、按键处理、`PermissionDialog` 状态）都已就绪，但 `AgentEvent::PermissionRequest` 无生产者、`ctx.rs:70` 的 `Prompt` 分支恒真放行、`needs_permission()` trait 方法是零调用死代码。

v1.0.1 定位为**稳定打磨版**：以「逐调用权限确认（完整 CC 对齐）」为头部特性，附带 WebSearch、GitHub 协作命令、稳定性收尾。Hooks 系统为绿地大工程，本版推迟到 v1.1。之前记忆里的 MCP stderr 阻塞 bug 已在 `bridge.rs`（改用 `stderr(Stdio::null())`）修复，无需再动。

范围决策（已与用户确认）：
- 权限确认：完整 CC 对齐（allow-once / allow-always / deny），**「始终允许」持久化到项目级设置**（跨会话生效）。
- WebSearch：**Tavily** 作为首选 provider，key 可配置。
- GitHub 命令：`/bug` + `/review` + `/pr-comments` 全做，`gh` 缺失时优雅降级。
- Hooks：推迟 v1.1。

## 特性 1（头部）：逐调用工具权限确认

**复用现成范式**：`ctx.rs` 的 `ui_ask_tx: mpsc::Sender<UiAskRequest>` + `oneshot` 往返（`ask_questions`/`exit_plan_mode` 已跑通同类链路），配合已有的 `PermissionDialog`/`draw_permission_dialog`/按键分支。**走 `ui_ask` 通道，不用死掉的 `AgentEvent::PermissionRequest` 路径。**

改动点：

- `crates/tools/src/ctx.rs`
  - 新增 `enum PermissionDecision { AllowOnce, AllowAlways, Deny }`。
  - `UiAskRequest` 新增 `ToolPermission { tool_name, action_summary, response_tx: oneshot::Sender<PermissionDecision> }`。
  - `ToolCtx` 新增 `always_allowed: Arc<RwLock<HashSet<String>>>`（会话内已「始终允许」的工具缓存，启动时从项目设置载入）。
  - 实现新 trait 方法 `request_permission`（照抄 `exit_plan_mode` 的 send+await 模式；无 `ui_ask_tx` 的 headless 场景默认 `AllowOnce`）。
- `crates/core/src/tool.rs`
  - `ToolContext` trait 新增 `async fn request_permission(&self, tool_name: &str, summary: &str) -> PermissionDecision`（默认返回 `AllowOnce`，保证 headless/子 Agent 不阻塞）。
  - 保留已存在的 `needs_permission(&input)`（tool.rs:99），激活其调用。新增可选 `action_summary(&input) -> String`（默认回工具名；Bash 返回命令、Edit/Write 返回文件路径）用于对话框正文。
- `crates/core/src/agent.rs`（`exec_tool_call` :609，`is_allowed` :630）
  - 执行前闸门：当 `PermissionMode::Prompt` **且** `tool.needs_permission(&input)` **且** 工具不在 `always_allowed` 内 → `ctx.request_permission(...)`。
    - `Deny` → 不执行，返回 `ToolResult`（is_error）把「用户拒绝 + 可选理由」回灌给模型（模型据此改道）。
    - `AllowAlways` → 加入 `always_allowed` 并写盘持久化，再执行。
    - `AllowOnce` → 本次执行，不记忆。
  - 并发说明：`needs_permission` 的工具（Bash/Edit/Write）非 `parallel_safe`，串行执行，同一时刻只有一个权限对话框，无并发排队问题。
- 权限持久化（跨会话）
  - 复用 `memory.rs` 已有的 **project-id 派生**（`~/.wyj-code/memory/<project-id>/` 同款方案），新增 `~/.wyj-code/projects/<project-id>/allowed_tools.toml`（或并入 store 的 lockfile 风格持久化）。
  - 载入：`crates/cli/src/main.rs` 构造 `ToolCtx` 时（app.rs:4826 附近的 ctx 装配链）读入 `always_allowed`。
- `crates/tui/src/app.rs`
  - `ui_ask_rx` 消费点（:5390）新增 `ToolPermission` 分支 → 置 `permission_dialog`（携带 `response_tx` 与 tool_name/summary）。
  - `PermissionDialog` 结构（:3532）加 `response_tx: oneshot::Sender<PermissionDecision>` 字段。
  - 按键处理（:7149-7186）改造三分支：分别 `send(AllowOnce/AllowAlways/Deny)`；**ESC = Deny**。
  - 移除死代码：`AgentEvent::PermissionRequest` 消费（:3898）与 `PermissionResponse`（event.rs:138）——无生产者的旧 stub。
- `crates/tui/src/render.rs`（`draw_permission_dialog` :1661）：呈现三选项「允许一次 / 始终允许此类 / 拒绝并说明」，文案走 i18n。
- 模式映射核对：确认 `mode_to_permission`（app.rs:4869）下 **Normal→Prompt**、Bypass→AutoApprove、Plan→Allowlist；子 Agent ctx 不接 `ui_ask_tx`（其 `request_permission` 走默认 AllowOnce，不弹窗）。
- i18n：`crates/i18n/locales/{en,zh}.yml` 加对话框文案 key。

## 特性 2：WebSearch 工具（Tavily）

- `crates/config/src/lib.rs`：新增 `search_provider: String`（默认 `"tavily"`）、`search_api_key: String`（env `WYJ_CODE_SEARCH_API_KEY` 优先，参照现有 `api_key` 读取逻辑）。
- `crates/tools/src/websearch.rs`（新建）：`WebSearchTool`，`reqwest::Client` POST Tavily `/search`（query + max_results），解析 results → 格式化 title/url/snippet 列表。复用 `webfetch.rs` 的 reqwest 范式。
- `crates/tools/src/descriptions.rs`：英文工具描述常量（不走 i18n，遵循「模型侧提示词英文」约定）。
- 注册：`crates/cli/src/main.rs` 里**仅当 search key 存在时** `register_arc`（避免模型调用一个必然报错的工具）；无 key 则不注册。`registry.rs` 暴露构造。
- 非 slash 命令，无需 help.body；会自然出现在 `/tools` 列表。

## 特性 3：GitHub 协作命令 `/bug` `/review` `/pr-comments`

均在 `crates/commands/src/builtin.rs` 新增命令结构并在 `standard_registry` 注册；共享一个 `gh` 检测辅助（`which gh`）。

- `/bug`：**零依赖**。`git remote get-url origin` 解析 owner/repo → 拼 `https://github.com/<owner>/<repo>/issues/new?body=...`（预填版本/OS/model 环境信息）→ `open`/`xdg-open`/`start` 打开；headless 则打印 URL。
- `/review [PR#]`：检测 `gh`，缺失 → 友好提示安装。存在 → `gh pr diff` 取 diff → `CommandResult::RunPrompt` 把 diff + 审查指令交给 agent 回合（agent 驱动审查，对齐 CC）。
- `/pr-comments [PR#]`：`gh pr view <PR#> --comments` → 展示输出。
- **CLAUDE.md 硬性约定**：三条命令必须同步进 `/help` —— 在 `crates/i18n/locales/{en,zh}.yml` 的 `help.body` 模板追加说明行（命令名/用途/参数），格式与现有条目一致；命令输出文案走 `tr()`。

## 特性 4：稳定性打磨收尾

- 版本号：`Cargo.toml [workspace.package] version = "1.0.1"` + `Cargo.lock` 同步（`scripts/check-version.sh` 会校验 tag==version）。
- CI 转绿核对：`kill_terminates_process_group` 已根因修复（`bash_session.rs` 改 `libc::kill(-pgid)` 直发进程组 + 等待窗口放宽 5s）。本机无 `gh` 无法核 CI；打 `v1.0.1` tag 后观察 test job，若仍偶发再收紧。
- 死代码清理：权限系统落地后，移除/归并 `AgentEvent::PermissionRequest`、`PermissionResponse` 旧 stub；顺手消 `anthropic.rs` 的 `#[allow(dead_code)]` 告警（若 trivial）。

## 特性 5：会话恢复按项目隔离

**现状问题**：`/resume`、`/sessions`（→ `OpenSessionPicker` → `app.rs:7626` 的 `store.list()`）列出**所有项目的全部会话**；`-c/--continue`（`main.rs:204` 的 `store.last()`）恢复的是**全局最新**会话，可能属于别的项目——尤其反直觉。会话数据其实早已存了 `cwd`（`SessionFile`/`SessionMeta`，`session_store.rs:14/31`），只是列举时未过滤。

**判定粒度（已确认）**：按 **git 仓库根**分组，非 git 目录回退到规范化 cwd——与 `memory.rs`/`claude_md.rs` 的 project-id 派生一致，直接复用/对齐同款 helper。默认只显示当前项目，**不保留跨项目查看通道**。

改动点：
- `crates/core/src/session_store.rs`
  - 新增项目键派生 helper：`cwd -> project_key`（向上找 `.git` 用仓库根，否则用规范化 cwd），对齐 memory 的 git-root 逻辑。
  - `list()` 增加按当前 project_key 过滤的变体 `list_for_project(cwd)`；`last()` 同理加 `last_for_project(cwd)`。过滤时对每条会话存的 `cwd` 也派生 project_key 再比较。
- `crates/cli/src/main.rs`
  - `-c/--continue` 分支（:204）改用 `last_for_project(current_cwd)`，恢复当前项目最近会话。
  - headless `--resume <id>` 保持按 id 精确恢复（**有意保留的逃生口**，允许显式跨项目恢复指定 id，不过滤）。
- `crates/tui/src/app.rs`
  - `OpenSessionPicker` 处理（:7626、:7710）把 `store.list()` 换成 `list_for_project(cwd)`，Picker 只列当前项目会话。
- 空态文案：当前项目无历史会话时给出友好提示（i18n）。

## 验证（端到端）

- **权限确认**（tmux 跑 `cargo run`，Normal 模式）：
  - 让模型改文件 / 跑 bash → 弹确认框；
  - 「允许一次」→ 下次同类工具**再次弹框**；
  - 「始终允许此类」→ 不再弹，**退出重进（`cargo run`）仍不弹**（验证项目级持久化）；
  - 「拒绝」→ 模型收到拒绝理由并改道；
  - ESC = 拒绝；Bypass 模式全程不弹、Plan 模式受白名单约束。
- **WebSearch**：设 `WYJ_CODE_SEARCH_API_KEY`，让模型搜索 → 返回结果；不设 key → 工具未注册（`/tools` 里不出现），模型不会误调。
- **GitHub 命令**：`/bug` → 浏览器打开预填 issue；有 `gh` 时 `/review <PR#>` 跑审查、`/pr-comments <PR#>` 列评论；**卸载/无 `gh` 时**二者给出安装提示而非崩溃。
- **会话按项目隔离**：项目 A 开会话 → 到项目 B（另一 git 仓库）跑 `/resume`/`/sessions`，列表**不含** A 的会话；在 A 的子目录里 `/resume` 仍能看到 A 根起的会话（git-root 分组）；`wyj-code -c` 在 B 恢复的是 B 的最近会话而非 A 的；`--resume <A的id>` 显式仍可跨项目恢复。
- **回归**：`cargo test`（新增单测：权限决策路由、allowlist 持久化 load/save、Tavily 响应解析[mock]、`/bug` URL 构造、`gh` 检测降级、session project_key 派生与过滤）、`cargo clippy`、`cargo fmt --check` 全绿。

## 交付顺序建议

1. 权限确认（头部，独立成体，先落地并 tmux 验证）
2. 会话按项目隔离（小而独立，可先落地打磨体验）
3. 稳定性打磨（版本号 + 死代码清理，随权限系统一起）
4. GitHub 命令（`/bug` 先行零依赖，`/review`/`/pr-comments` 随后）
5. WebSearch（配置 + 工具 + 条件注册）
6. 全量 test/clippy/fmt → bump 1.0.1 → 打 tag 观察 CI
