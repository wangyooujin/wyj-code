# wyj-code v1.1 计划

## Context

v1.0.2（2026-07-08）发布后，wyj-code 已是一个相当完整的 Claude Code 复刻：26 命令 / 15 工具 /
TUI（终端原生 scrollback）/ MCP·skills·plugins 三市场 / 子 Agent 编排 / 记忆 / 压缩 / i18n /
逐调用权限确认 / `wyj-code update` 自更新 / 多平台 Release CI。核心链路全通。

本版把定位正式转向**「给别人用的开源产品」**，据此确定 v1.1 = **一个头部大特性 + 开源产品化收尾**：

- **头部特性：Hooks 生命周期自动化系统**。这是 v1.0.1 计划里唯一明确「推迟到 v1.1」的绿地大工程，
  也是真 CC 的招牌自动化能力（用户挂 shell 脚本做 lint/格式化/拦截/通知）。缺了它，wyj-code 对
  想迁移过来的 CC 用户就少了一块关键拼图。
- **收尾：开源产品化基线**。仓库根目前**没有 README / LICENSE / CONTRIBUTING**——对开源产品是硬缺口；
  外加一个每天可见的已知 TUI bug（Inline viewport 输入框不贴底）。这些不修，项目「能用」但「不像一个
  可被他人采用的开源项目」。

Hooks 与收尾均为相对独立的改动，Hooks 复用现成的工具执行闸门与 CLAUDE.md 路径发现逻辑，不引入新的
架构主线，适合一个版本内完成。

Checkpoint/Rewind 回溯与自定义 slash 命令为下一步候选，留待 v1.2+。

## 特性 1（头部）：Hooks 生命周期自动化系统

**目标**：用户可在 `.claude/settings.json` 声明 shell hook，在 Agent 生命周期的 4 个关键点被触发，
用于自动化（保存即格式化、危险命令拦截、注入项目上下文、回合结束桌面通知等），行为对齐真 Claude Code。

### 配置来源与合并（对齐 CC）

- 沿用项目「复用真 CC 路径」的传统（`~/.claude/CLAUDE.md`、`.claude/agents/*.md` 已如此）。Hooks 读
  **`.claude/settings.json`** 的 `hooks` 块，格式与真 CC 一致，用户可直接复用其现有 CC hook 配置。
- 合并顺序（后者不覆盖、而是**追加**到同事件同 matcher 的 hook 列表，与 CC 语义一致）：
  用户级 `~/.claude/settings.json` → 项目级 `<git-root>/.claude/settings.json` →
  `<git-root>/.claude/settings.local.json`（个人覆盖，不提交 git）。
- 项目根定位**复用现有 git-root 派生逻辑**（`core::project` 的 project_key / `claude_md.rs` 的祖先链
  发现），不新造一套路径规则。
- 配置格式：
  ```json
  {
    "hooks": {
      "PreToolUse": [
        { "matcher": "Edit|Write", "hooks": [ { "type": "command", "command": "./scripts/guard.sh" } ] }
      ],
      "PostToolUse": [
        { "matcher": "Edit|Write", "hooks": [ { "type": "command", "command": "cargo fmt" } ] }
      ]
    }
  }
  ```
  `matcher` 是对工具名的正则（PreToolUse/PostToolUse 生效；UserPromptSubmit/Stop 无工具维度，`matcher`
  忽略）。

### Hook 执行协议（对齐 CC）

- 单个 hook = spawn 一个 shell 命令（`tokio::process::Command`，经 `sh -c` / Windows `cmd /C`）。
- **入参走 stdin JSON**：`{ session_id, cwd, hook_event_name, tool_name?, tool_input?, tool_response? }`。
- **出参双通道**：
  - **exit code**：`0` = 放行/成功；`2` = **阻断**（PreToolUse 拒绝工具、UserPromptSubmit 拒绝提交、
    Stop 要求继续），stderr 文本作为「阻断原因」回灌给模型；其它非零 = 非阻断错误（记 warn，不影响主流程）。
  - **stdout JSON（可选，优先于 exit code 的富语义）**：解析 `{ decision: "block"|"approve", reason,
    additionalContext, continue }`，映射到统一的 `HookOutcome`。stdout 非 JSON 时忽略，只看 exit code。
- 超时保护（默认 60s，可配 `timeout`），超时视为非阻断错误。
- **安全**：hook 执行任意 shell。首次在某项目加载到 hook 时给一次醒目提示（i18n），并支持通过
  `--no-hooks` CLI 开关 / 配置项全局禁用。子 Agent 的 ctx 不触发 hooks（与「子 Agent 不弹权限框」一致，
  避免嵌套副作用）。

### 各事件语义与集成点（均已勘察定位）

| 事件 | 触发点（file:line 基线） | 阻断/富语义 |
|---|---|---|
| **PreToolUse** | `agent.rs::exec_tool_call`（:609），在既有权限闸门 `ctx.confirm_tool`（:634）**之前** | `block`→不执行，把 reason 作为 `is_error` 工具结果回灌模型；`approve`→跳过权限确认直接执行；passthrough→走正常权限流 |
| **PostToolUse** | `exec_tool_call` 工具结果组装完成后、追回 session 前 | `block`→把 reason 作为附加反馈追加进结果回给模型；`additionalContext`→同理追加；否则纯旁路（如 `cargo fmt`） |
| **UserPromptSubmit** | `run_turn_with_injection`（:244）取到用户回合、进入推理循环前 | `block`→中止本轮并把 reason 回给用户；`additionalContext`→前插进该 user 消息（复用 `prepend_to_last_user`，:283 附近同款手法） |
| **Stop** | 推理循环出口（`has_tool_calls` 为 false、`stop_reason != ToolUse`，:491 附近 loop break） | MVP：旁路观察（桌面通知/音效/收尾脚本）；`continue`/exit 2 → 追加一条 user 消息续跑（复用 pending 注入兜底）作为 stretch |

### 改动点

- **`crates/config/src/lib.rs`（或新建 `crates/config/src/settings.rs`）**：新增 `.claude/settings.json`
  的 serde 结构（`HooksSettings` / `HookMatcher` / `HookCommand`），及「用户+项目+local 三源合并」loader。
  仅解析 `hooks` 键，对未知键宽容（`#[serde(default)]`），为后续 settings 扩展留位。
- **`crates/core/src/hooks.rs`（新建）**：`HookRunner`（`Send + Sync`）——
  - `matches(event, tool_name)` 选出命中的 hook 列表；
  - `run(event, payload) -> HookOutcome`（`enum HookOutcome { Passthrough, Approve, Block(String),
    Continue{ context: Option<String> } }`）：串行跑命中的 hooks，任一 `Block` 立即短路返回；
  - 纯逻辑 + `tokio::process`，无 UI 依赖。单测覆盖 matcher 命中、exit-code 与 stdout-JSON 两种出参解析、
    多 hook 短路、超时降级。
- **`crates/core/src/agent.rs`**：`Agent` 持 `Option<Arc<HookRunner>>`；在上表 4 个点调用；PreToolUse 的
  `Approve` 需能绕过 `confirm_tool`（在 :634 闸门前判定）。payload 里的 `cwd`/`session_id` 从既有
  `ToolContext`/`Session` 取。
- **`crates/tools/src/ctx.rs`**：如需从工具侧暴露 cwd/session_id 给 payload，补只读 getter（大概率已有）。
- **`crates/commands/src/builtin.rs` + i18n**：新增 **`/hooks`** 命令，列出当前会话生效的全部 hooks
  （按事件分组 + 来源文件 + matcher + 命令），对齐 CC 的 `/hooks`。
- **`crates/cli/src/main.rs`**：`--no-hooks` 开关；构造 Agent 时装配 `HookRunner`（读三源 settings）。
- **`/help` 同步**（CLAUDE.md 硬性约定）：在 `crates/i18n/locales/{en,zh}.yml` 的 `help.body` 追加
  `/hooks` 说明行，格式与现有条目一致。
- **CLAUDE.md**：新增「Hooks」小节，说明配置来源/合并顺序/4 事件/执行协议/安全约束，纳入 Architecture
  的数据流编号列表。

## 特性 2（收尾）：开源产品化基线

**背景**：仓库根缺 README / LICENSE / CONTRIBUTING，外部用户无从了解「这是什么、怎么装、怎么用、能不能改」。

- **`README.md`（新建）**：一句话定位（Rust 写的、零遥测的 Claude Code 复刻）→ 特性矩阵（命令/工具/三市场/
  子 Agent/记忆/Hooks）→ 安装（`build.sh release` 产物 / GitHub Releases / `wyj-code update` 自更新）→
  快速上手（`cargo run`、三模式、`/help`）→ 配置速览（`~/.wyj-code/config.toml` + `.claude/settings.json`
  hooks）→ 与真 CC 的关系/差异 → License 徽章。内容从 CLAUDE.md 提炼，面向用户而非贡献者。
- **`LICENSE`（新建）**：默认 **MIT**（可由作者最终敲定；MIT 对「给别人用」最省心）。
- **`CONTRIBUTING.md`（新建）**：构建/测试/lint 命令、crate 职责表（指向 CLAUDE.md）、提交约定
  （简体中文、首行 `type: 简述`、**不加 Co-Authored-By trailer**——沿用仓库既有约定）。
- **`CHANGELOG.md`（可选）**：从 v1.0.0 起按版本汇总，后续 `build.sh release` 时顺带维护。

## 特性 3（收尾）：已知 TUI bug 修复

- **输入框贴底（Inline viewport）**——**结论变更：不做，改为显式记录已知限制**。
  原计划设想引入 `terminal.get_cursor_position()` 做光标/视口起点校正使输入框稳定贴底；
  实际动手后用最小复现程序反复 tmux 实测，发现让 Inline viewport 撑到接近终端整高时，
  ratatui + crossterm 内部依赖的终端光标位置查询有相当概率（tmux 下经常超过一半）与实际
  渲染错位——不仅贴不到底部，更严重时用户刚输入的字符会完全不可见（逻辑上已正常收到，只是
  没画出来）。用完全相同的输入在 ratatui+crossterm 的独立最小复现示例里也能复现同样的问题，
  判断这是 ratatui/crossterm 层面的限制，不是本项目代码能修的 bug。因此放弃"贴底"目标，保留
  按内容实际需要动态定高的现状（牺牲视觉贴底效果换取渲染稳定可靠），并已在 README「已知限制」
  与 `app.rs` 对应位置写明结论与复现依据，避免后续版本重复踩坑。
- **冻结内容 resize 不重排**（`insert_before` 已写入终端 scrollback 的历史，resize 不会重新换行）——
  为既定取舍，**本版不改**（改动面大、收益低），已在 README「已知限制」章节显式记录。

## 验证（端到端）

- **Hooks — 配置与合并**：`~/.claude/settings.json` 与项目 `.claude/settings.json` 各放一条同事件 hook，
  `/hooks` 列出两条（来源标注正确）；`.claude/settings.local.json` 覆盖生效；`--no-hooks` 时 `/hooks` 空。
- **Hooks — 四事件（tmux 跑 `cargo run`）**：
  - PreToolUse `matcher:"Bash"` 命令内含危险串时 exit 2 → 工具被拒、模型收到原因改道；`approve` → 不弹权限框直接执行。
  - PostToolUse `matcher:"Edit|Write"` 挂 `cargo fmt` → 改文件后自动格式化；block 分支反馈能回到模型。
  - UserPromptSubmit 注入 `additionalContext` → 该上下文出现在模型可见的 user 消息里；exit 2 → 提交被拦。
  - Stop 挂桌面通知脚本 → 每轮结束触发。
  - 首次加载 hook 的安全提示出现一次。
- **Hooks — 单测**：matcher 命中、exit-code/stdout-JSON 出参解析、多 hook 短路、超时降级、三源合并顺序。
- **开源基线**：README/LICENSE-MIT/LICENSE-APACHE/CONTRIBUTING/CHANGELOG 人工审阅；README 里的
  安装/上手命令实机跑通。
- **TUI 贴底**：结论变更为不做（见特性 3），不再作为验证项；已知限制已写入 README。
- **回归**：`cargo build --release`、`cargo test --workspace`、`cargo clippy --workspace --all-targets`、
  `cargo fmt --check` 全绿，无新增告警；`/help` 含 `/hooks`；CLAUDE.md 已补 Hooks 小节。
