# wyj-code v1.0.2 计划

## Context

v1.0.1（2026-07-07）发布后，围绕两条线继续推进：一是发布/分发闭环——此前只有 GitHub Actions 侧的交叉编译发布（release.yml），缺"开发者一键切版本发布"和"用户端自更新"两块，导致每次发版都要手工改版本号、打 tag、push，用户升级也只能重新手动下载安装；二是日常使用中从真实截图反馈定位到的两个 TUI 体验缺陷（工具结果展开正文重复摘要行、ExitPlanMode 计划面板无法用鼠标滚轮查看且交互方式与 Claude Code 不对齐）。v1.0.2 把这两块打包发布：**发布基础设施收尾** + **TUI 缺陷修复**，均为小而独立的改动，不引入新的架构决策，无需拆分成多个版本。

---

## 特性 1：发布基础设施收尾——`wyj-code update` 自更新命令 + `build.sh release` 一键发版

**背景**：release.yml 已经能在打 tag 后自动交叉编译 5 个平台产物并创建 GitHub Release，但发布前的"改版本号→提交→打 tag→push"完全靠手动操作，容易漏步骤（比如忘记同步 Cargo.lock 导致 CI 的 tag/版本号一致性校验失败）；发布后用户升级也没有比"回 GitHub Releases 页面重新下载"更省事的路径。

**改动点**：

- `crates/store/src/self_update.rs`（新建）：自更新的纯逻辑层，不做任何 `println!`/stdin 交互——
  - `fetch_latest_release`：查 GitHub `/releases/latest`（自动排除 draft/prerelease）。
  - `is_newer`：用 `semver` 比较远端/本地版本号，本地领先或相等一律视为"已是最新"。
  - `current_target`/`asset_names`：映射到 release.yml 构建矩阵的 5 个 target triple，拼出归档名 + `.sha256` sidecar 名。
  - `download_and_verify`：下载归档与 sha256 sidecar，校验一致后返回字节。
  - `extract_binary`：从 `.tar.gz`（unix）/`.zip`（windows）里取出二进制。
  - `atomic_replace_current_exe`：unix 走"同目录建临时文件 + rename"（照搬 `build.sh install_local()` 已踩过的坑——原地覆盖正在运行进程占用的可执行文件会让 macOS 内核判定代码签名失效，导致后续 exec 该路径被 SIGKILL）；windows 走"先把自己挪到 `.old`，再把新文件挪进来"（Windows 不允许覆盖正在执行的文件，但允许重命名）。
  - 7 个单测覆盖版本比较、target 映射、asset 命名、sha256 校验、tar.gz/zip 解压、tag 前缀剥离。
- `crates/cli/src/update_cmd.rs`（新建）：`wyj-code update [-y]` 子命令编排，调用上述纯逻辑层，负责全部用户可见文案（i18n）与 y/N 交互确认；`-y` 跳过确认（脚本场景）。
- `crates/cli/src/main.rs`：clap 增加 `Commands::Update` 子命令，解析后优先分发，不进入正常 TUI/REPL 启动路径。
- `crates/i18n/locales/{en,zh}.yml`：新增 `cli.update_about`/`cli.update_yes_help` 与整个 `update.*` 文案块（检查中/已是最新/发现新版本/下载中/校验失败/替换中/成功/权限错误等）。
- `Cargo.toml`：新增依赖 `semver`（版本比较）、`sha2`（校验和）、`flate2` + `tar`（`.tar.gz` 解压）、`zip`（`.zip` 解压）；`crates/store`/`crates/cli` 的 `Cargo.toml` 同步引入。
- `build.sh` 新增 `release` 子命令：分支必须是 `master`、工作区必须干净 → 跑 `cargo test`/`cargo clippy` → 建议版本号（当前版本 patch+1，可回车采用或手动输入）→ 校验本地/远端均无同名 tag → 写入 `Cargo.toml` 并提交 `chore: bump version to <version>` → 打 `-a` tag → push 分支与 tag（触发 release.yml）。
- `CLAUDE.md`：Build & Run 一节补充 `./build.sh release` 命令说明。

## 特性 2：TUI 缺陷修复——工具结果重复行 + ExitPlanMode 面板重构

**背景**：真实使用截图暴露两个问题：① Bash/Edit/Write 等工具的 `⎿` 摘要行本来就是复用了 stdout 首行原文，但展开正文又把包含该行在内的全部内容重新渲染了一遍，摘要和正文首行肉眼可见地重复；② ExitPlanMode 计划审批面板是独立的底部浮层，内容超出可视高度只能靠面板自带的 `↑/↓`/`PageUp/PageDown` 滚动，无法用鼠标滚轮（面板不参与聊天区的终端原生 scrollback 冻结管线），批准/拒绝是纯文字 `y`/`n` 快捷键，且没有"手动输入反馈"这类自由文本选项。

**改动点**：

- 重复行根因是三处"整串字符串比较"判断（`content != summary`）在内容超过一行时恒为真，导致摘要行已展示过的首行又被完整渲染进正文。修复为在 `ChatMessage` 上记一个确定性标记 `summary_is_first_line`（由 `tool_result_summary` 各分支在生成摘要时同步给出，而非事后猜测字符串是否相等），展示正文时据此确定性跳过已展示过的首行：
  - `crates/tui/src/app.rs`：`ChatMessage` 新增 `summary_is_first_line` 字段；新增 `summary_reuses_first_line(name, is_error)` 判定各工具分支是否复用了首行原文；`ToolEnd` 事件处理据此设置字段。
  - `crates/tui/src/render.rs`：新增 `strip_summary_duplicate_line` 统一去重逻辑，`is_collapsible_tool_result_content`/`last_collapsible_tool_result_idx`/`ToolResult` 展开渲染分支三处同步改用该标记，不再比较字符串。
- ExitPlanMode 面板重构，对齐 Claude Code：
  - 计划正文改为普通 `MessageRole::PlanProposal` 消息并入聊天流（`render_chat_message` 新增渲染分支，标题+分隔线+markdown 正文），走和其它消息一样的 `frozen_up_to` 冻结/`insert_before` 管线，天然获得终端原生 scrollback 鼠标滚轮滚动，不再需要面板自己维护滚动状态。
  - `PlanApprovalDialog` 瘦身为固定 3 行的贴底选择器（批准 / 继续规划 / 手动输入反馈），复用 AskQuestion 已有的 `InProgressAnswer` 状态机（`Single{cursor}` + `FreeText` 自由文本子模式），`↑/↓` 选中 + `Enter` 确认，不再保留 `y`/`n`/`Esc` 字母快捷键。
  - 新增"手动输入反馈"：回车就地展开单行文本框，再次回车提交后 `send(false)` + `interrupt()`，并把反馈文本推进 `pending_queue`——复用已有的"空闲且队列非空自动发起新一轮"兜底逻辑，无需新增 agent 侧协议或修改 `response_tx: oneshot::Sender<bool>` 的类型契约，反馈会作为下一条用户消息立即续接对话，Agent 据此修订计划。
  - 12 个新增单测覆盖去重逻辑与三选一状态机（含 FreeText 子模式的进入/提交/Esc 退回）。

## 验证（端到端）

- **自更新命令**：`cargo test -p wyj-store self_update` 全绿（版本比较、target 映射、asset 命名、sha256 校验、tar.gz/zip 解压、tag 前缀剥离）；`GITHUB_OWNER`/`GITHUB_REPO` 常量核对与实际仓库 `wangyooujin/wyj-code` 一致；`asset_names` 产出的文件名与 `release.yml` 构建矩阵的 5 个 target triple 逐一核对一致。发布后需人工验证 `wyj-code update` 在真实环境下能查到 v1.0.2 并成功替换二进制（本次改动未做，留待发布后手动核实）。
- **`build.sh release`**：本次 v1.0.2 发布即为该脚本的首次实际使用验证——分支/工作区检查、版本号建议与交互确认、tag 唯一性校验、bump 提交、打 tag、push 触发 release.yml 全流程走一遍。
- **工具结果重复行**：tmux 实测 `git status --short` 等多行 Bash 输出，摘要行只展示首行，展开正文从第二行起，不再重复；`cargo test -p wyj-tui` 中 `tool_result_fold_tests`/`tool_summary_tests` 全绿。
- **ExitPlanMode 面板**：tmux 实测 plan 模式下触发计划审批——计划正文并入正常消息流可用鼠标滚轮查看；`↑/↓` 切换批准/继续规划/手动输入反馈三个选项；手动输入反馈提交后自动作为下一条消息续接对话，Agent 据反馈修订计划；批准后正确切换至执行模式。`cargo test -p wyj-tui plan_approval` 全绿。
- **回归**：`cargo build --release`、`cargo test --workspace`、`cargo clippy --workspace --all-targets` 全绿，均无新增告警。
