# wyj-code v1.4.4 国内模型可信运行时与安全执行计划

> 状态：实施已批准；P0、选定 P1 与 P2 接口已落地，本地门禁已通过，等待远端发布验证
> 计划日期：2026-08-02
> 代码基线：master / d09ef91 / v1.4.2
> 版本号：v1.4.4（按用户明确指定；不移动任何既有公开标签）
> 实施范围：完整 P0、选定的 P1 基础能力、P2 架构接口
> 实施前工作区：TUI 原生鼠标选择、超链接和相关文档修改已单独还原边界；保持在用户工作树中，不纳入 v1.4.4 release commit/tag

## 一、结论

v1.4.4 不以继续增加零散表面功能为目标，而是把 wyj-code 从“能够接入国内兼容 API 的终端 Agent”升级为：

> 能识别国内模型真实能力、按能力调整请求和工具策略、从格式及供应商失败中恢复，并在 OS 级执行边界内安全运行的本地优先 Coding Agent。

本版本的两个硬门禁是：

1. 安全可信：无 UI 不再等于批准；Plan 模式不能修改源代码；Bash 及子进程受文件系统和网络 sandbox 约束。
2. 国内模型有效成功率：模型能力不再只靠名称猜测；坏工具 JSON 不得带病执行；每项兼容声明必须区分静态兼容和真实验证。

版本策略采用已确认的方案：

| 层级 | v1.4.4 范围 | 是否阻塞发布 |
|---|---|---:|
| P0 | 权限 fail-closed、Claude Code 式 sandbox、ModelCapabilities、模型诊断、工具参数校验修复、供应商错误标准化、国内模型评测基础 | 是 |
| P1 | tool search/lazy schema、同角色 fallback、checkpoint/rewind MVP、session branch、SubAgentHub 控制协议 | 选定项阻塞 |
| P2 | worktree 自动隔离、完整多 Agent workflow、ACP/daemon、代码语义索引、完整插件能力 | 仅冻结接口和后续路线，不阻塞 |

## 二、访谈确认的产品决策

### 2.1 优先级

按以下顺序执行，不以竞品功能数量倒逼范围膨胀：

1. 安全与 fail-closed。
2. 国内模型端到端任务成功率。
3. Token、成本和响应速度。
4. 与 Claude Code、Codex、Qoder、Qwen Code 的功能覆盖差距。

### 2.2 核心模型矩阵

核心目标模型：

- GLM
- MiniMax
- Kimi
- DeepSeek
- Qwen / 阿里百炼
- 豆包 / 火山引擎

参考对照：

- Anthropic Claude
- OpenAI

兼容性组：

- Ollama
- vLLM
- 其他 OpenAI-compatible / Anthropic-compatible 私有代理

当前只有 MiniMax 具备用户可提供的真实 API 条件，但访谈期间原 Key 已暴露，必须先撤销并轮换。任何实施、评测和发布流程均不得使用、保存或引用已经暴露的 Key。

除 MiniMax 外，没有真实 Key 的模型只能标为 protocol-compatible 或 experimental，不能在 README、CHANGELOG、官网和 Release Notes 中宣称 verified。

### 2.3 Plan 模式文档写入

采用已确认的 C 方案：

- doc/plan/**、docs/plan/**、.wyj-code/plans/** 自动作为规划文档根目录。
- 其他 Markdown/文本文档必须由用户对本轮、具体路径明确授权。
- 源代码、构建脚本、配置、CI、锁文件和其他可执行内容始终禁止。
- Plan 模式可以使用 Write/Edit 的受限文档变体，但 Bash 仍保持只读，不得通过 shell 重定向或解释器绕过路径策略。
- 所有文档写入继续遵守先 Read 后 Edit/Write、diff 展示和 checkpoint 记录。

### 2.4 Sandbox 对齐目标

产品语义对齐 Claude Code 当前公开方案：

- 权限系统决定一次操作是否得到批准。
- OS sandbox 决定即使得到批准，命令仍只能访问授权文件系统和网络边界。
- macOS 使用 Seatbelt。
- Linux/WSL2 使用 bubblewrap，并通过代理控制网络出口。
- 原生 Windows 不承诺同等级 sandbox，建议使用 WSL2；不可用时必须明确展示能力边界。
- 工作目录和会话临时目录默认可写。
- 网络按域名授权。
- interactive 可显式批准 unsandboxed fallback。
- headless、单次 -p、schedule 和子 Agent 默认 fail-closed。

### 2.5 工具参数修复

采用保守策略：

- 允许修复代码围栏、尾逗号、缺失的闭合括号等纯 JSON 语法问题。
- 不猜测 file_path、command、url、old_string、new_string、content 等语义字段。
- 缺少必填字段时把精确 schema 错误回灌给模型定向重试。
- 重试仍失败时停止该调用，禁止退化成空对象或 null 执行。

### 2.6 模型路由与 fallback

- 自动参数降级可以默认启用，但必须记录发生了什么。
- 同角色 fallback 可以配置并在可恢复错误上启用。
- 跨供应商 fallback 默认关闭。
- Auth、权限拒绝、内容安全、无效请求和工具策略拒绝不得触发换模型逃逸。

### 2.7 实施审批

本计划落盘后停止。只有用户明确批准后才开始修改代码、配置、测试和发布文件。

## 三、当前代码根因

### 3.1 Profile 是静态字段集合，不是能力运行时

当前 crates/config/src/lib.rs::Profile 已包含：

- provider
- model
- plan_model / exec_model
- context_window
- vision
- thinking_budget
- interleaved_thinking
- prompt_cache
- openai_stream_options

crates/api/src/models.rs 已有 GLM、火山、MiniMax、Kimi、DeepSeek 模板。

这些字段解决了部分兼容问题，但缺少：

- vendor 与 wire protocol 分离。
- 能力来源和可信度。
- probe 结果。
- 工具并行、tool_choice、strict schema、图片工具结果等能力。
- 不支持参数的动态降级。
- 模型切换后的重新协商。

### 3.2 Provider 抽象过薄

crates/api/src/provider.rs::RequestOptions 只有 max_tokens、thinking_budget 和 interleaved。

OpenAI Chat Completions 路径会忽略 Anthropic thinking 参数，也没有统一表达：

- reasoning effort
- tool choice
- parallel tool calls
- strict schema
- response format
- vendor-specific headers
- fallback request plan

### 3.3 坏工具参数当前会被静默接受

crates/core/src/agent.rs 和 crates/api/src/provider.rs 对工具参数解析失败分别退化为空对象或 null。

这会导致：

- 权限策略拿到错误输入。
- 工具收到缺字段对象。
- 模型只看到二次工具失败，看不到原始 schema 错误。
- 国内模型在长链路中的格式漂移无法被恢复。

### 3.4 权限在无 UI 场景 fail-open

crates/tools/src/ctx.rs 当前行为：

- PermissionMode::Prompt 的 is_allowed 返回 true。
- confirm_tool 在没有 ui_ask_tx 时返回 true。
- exit_plan_mode 在 headless 中自动批准。

这使 Normal 模式在部分 -p、headless、schedule、子 Agent 场景中可能自动执行副作用工具。

### 3.5 Plan 模式只读约束没有执行层闭环

crates/cli/src/main.rs 的 Plan allowlist 包含 Write 和 Bash。

TUI Plan allowlist 虽没有 Write，但 Bash 只读主要依赖 system prompt。当前 ToolContext::is_allowed 也不检查 Bash command 或 Write/Edit 目标路径。

### 3.6 Bash 没有 OS 级隔离

crates/tools/src/bash.rs 与 crates/tools/src/bash_session.rs 都直接使用 bash -c。前台和后台 Bash 必须共享同一 sandbox runner，否则模型可通过 run_in_background 绕过边界。

### 3.7 每轮发送所有工具 schema

crates/tools/src/registry.rs::definitions 会返回全部工具定义；crates/core/src/agent.rs 每次 Provider 请求都发送 self.tools。

MCP 和 Plugin 增多后，schema token 成本、选错工具概率和小模型压力会线性增长。

### 3.8 会话可恢复，但没有文件状态节点

crates/core/src/session_store.rs 只持久化消息、标题和 token，没有：

- checkpoint id
- parent checkpoint
- branch parent
- 文件树快照
- 恢复记录

### 3.9 子 Agent 只有生命周期控制

crates/tools/src/agent_hub.rs 的 RunningEntry 只有 background 与 JoinHandle，支持注册、完成和 abort，但没有消息通道、follow-up、暂停、重试和父子关系。

### 3.10 评测集不足

benchmarks 当前只有 4 个小型 Rust fixture 任务，结果缺少模型、vendor、protocol、参数和 capability snapshot，无法支撑国内模型优化结论。

## 五、P0：可信执行与国内模型运行时

P0 全部属于 v1.4.4 发布门禁。

## 5.1 权限策略重构

### 5.1.1 新增统一 PermissionPolicy

建议在 wyj-core 定义与前端无关的策略对象：

~~~rust
pub struct PermissionRequest {
    pub mode: PermissionMode,
    pub surface: ExecutionSurface,
    pub tool_name: String,
    pub input: serde_json::Value,
    pub cwd: PathBuf,
    pub sandbox_available: bool,
}

pub enum PermissionVerdict {
    Allow,
    Ask(PermissionPrompt),
    Deny(DenyReason),
}
~~~

ExecutionSurface 至少包括：

- TuiInteractive
- SinglePrompt
- HeadlessRepl
- Schedule
- SubAgent
- Hook

ToolCtx 不再自行把“没有 UI”解释为 true，而是执行 PermissionPolicy 的结果。

### 5.1.2 各模式语义

Normal：

- TUI 中副作用工具询问。
- 无 UI 时默认拒绝副作用工具。
- 可通过显式 allowed-tools、allowed-write-roots 或 bypass 开启。

Plan：

- 自动允许 Read、Glob、Grep、WebFetch、WebSearch、AskQuestion、TodoWrite、只读 Agent。
- Bash 仅允许执行层判定的只读命令。
- Write/Edit 只允许规划文档根目录或本轮获批文档路径。
- ExitPlanMode 在 TUI 中等待用户批准；headless 输出计划并退出，不自动切换执行模式。

Bypass：

- 跳过交互权限询问。
- 不自动关闭 sandbox。
- 显式 deny、protected path、凭证保护仍生效。

Allowlist：

- 工具名和目标范围同时匹配才允许。
- 仅工具名匹配不能授权任意文件路径和任意网络域名。

### 5.1.3 Headless 新参数

新增或等价支持：

~~~text
--allowed-tools Read,Grep,Glob,Bash
--allow-write ./generated
--allow-network api.example.com
--allow-plan-write ./README.md
--require-sandbox
~~~

要求：

- 参数是本次进程权限，不写回全局配置。
- 路径在解析后显示为绝对规范路径。
- 未提供权限的副作用工具直接返回非零退出码和结构化原因。
- 不接受模糊通配符授权 home、根目录或仓库父目录。

### 5.1.4 Schedule 迁移

ScheduleTask 增加：

~~~rust
pub struct SchedulePermissions {
    pub allowed_tools: Vec<String>,
    pub allow_write: Vec<PathBuf>,
    pub allowed_domains: Vec<String>,
    pub require_sandbox: bool,
}
~~~

迁移策略：

- 既有任务首次升级标记 needs_permission_review。
- 未完成权限审查的任务自动禁用，不继续按旧 fail-open 语义运行。
- TUI 和 CLI 提供审查、重新启用入口。
- schedule run 始终传递显式权限参数。
- computer-use 继续保持 headless fail-closed。

## 5.2 Plan 模式文档写策略

### 5.2.1 自动文档根

默认：

~~~text
doc/plan/**
docs/plan/**
.wyj-code/plans/**
~~~

允许扩展名：

~~~text
.md
.mdx
.txt
.rst
~~~

### 5.2.2 其他文档

对于 README.md、CHANGELOG.md、普通 docs/** 等路径：

- TUI 弹出“本轮允许修改此文档”确认。
- 只把规范化后的单一路径加入 per-turn_document_grants。
- 授权在当前用户回合结束后失效。
- headless 必须显式使用 --allow-plan-write。

不得把“用户在自然语言里好像提到了某路径”当作机器可信授权。

### 5.2.3 路径安全

实现统一 safe_resolve_write_target：

- 相对路径以 Git 根或显式 cwd 解析。
- 对现有文件 canonicalize。
- 对新文件 canonicalize 最近存在父目录，再拼接文件名。
- 拒绝 .. 逃逸。
- 拒绝 symlink 指向允许根之外。
- macOS 默认按文件系统实际大小写规则比较。
- 拒绝设备文件、FIFO、socket。
- 拒绝 .git、凭证目录、会话存储和配置目录；.wyj-code/plans 是唯一例外。

### 5.2.4 Bash 不得绕过

Plan Bash 即使 sandbox 可写 doc/plan，也仍按只读命令策略运行：

- 禁止 >、>>、2>、tee、sed -i、perl -i。
- 禁止 python/node/ruby 等解释器执行任意写文件脚本。
- 禁止 cp、mv、rm、mkdir、touch、install、patch。
- 禁止 git commit、checkout、restore、reset、clean、apply。
- 允许 git status、git diff、git log、git show、git grep、ls、find、rg、cat 等已验证只读命令。

规划文档只能通过受策略约束的 Write/Edit 路径写入。

## 5.3 Claude Code 式 Sandbox

### 5.3.1 新 crate

新增 crates/sandbox，职责只包含：

- sandbox 能力探测。
- 配置解析后的中立请求结构。
- 平台 backend。
- 命令包装与执行。
- 网络代理边界。
- 结构化错误。

不得把 TUI、Agent、模型或业务工具逻辑放进该 crate。

建议接口：

~~~rust
pub trait SandboxBackend: Send + Sync {
    fn status(&self) -> SandboxStatus;
    fn prepare(&self, request: &SandboxRequest) -> Result<SandboxCommand>;
}

pub struct SandboxRequest {
    pub cwd: PathBuf,
    pub temp_dir: PathBuf,
    pub read_paths: Vec<PathBuf>,
    pub write_paths: Vec<PathBuf>,
    pub deny_read_paths: Vec<PathBuf>,
    pub allowed_domains: Vec<String>,
    pub command: String,
}
~~~

### 5.3.2 平台 backend

macOS：

- 使用系统 Seatbelt 能力。
- 生成最小化、可审计的 profile。
- 默认允许读取项目和必要系统动态库。
- 默认仅允许写工作目录和会话 temp。
- 拒绝读取常见凭证路径。
- 实施前先做独立兼容性 spike，确认目标 macOS 版本可用执行路径。

Linux/WSL2：

- 使用 bubblewrap 做 mount/user namespace 隔离。
- 使用 socat 或等价代理控制网络。
- 启动时检测依赖并在 /sandbox Dependencies 中展示。
- 可选 seccomp 作为增强，不把缺少可选 seccomp 当成完全不可用。

Windows：

- 原生 backend 返回 Unsupported。
- 文档推荐 WSL2。
- native Windows 不允许静默假装 sandbox 已启用。

### 5.3.3 默认文件系统边界

- 工作目录：读写。
- 会话临时目录：读写，并为 sandboxed command 设置专用 TMPDIR。
- Git 仓库外：默认不可写。
- home：默认只允许运行所必需的最小读取，不允许任意遍历。
- ~/.ssh、云厂商凭证、shell 历史、API Key 配置：默认 deny read。
- 额外路径通过 allowRead/allowWrite 显式增加。
- 更具体的 deny 优先于宽泛 allow。

### 5.3.4 网络边界

- 默认无网络。
- 首次访问新域名时，TUI 可以请求批准。
- 批准按 host + port 记录到当前会话，不永久扩大权限。
- headless 只能访问 --allow-network 或任务 manifest 中的域名。
- IP、Unix socket、本地监听、localhost 分别配置，不与域名授权混用。
- DNS 解析和代理日志不得记录认证 header、query secret 或请求正文。

### 5.3.5 Sandbox mode

配置：

~~~toml
[sandbox]
enabled = true
auto_allow_sandboxed = false
allow_unsandboxed_commands = true
fail_if_unavailable = false

[sandbox.filesystem]
allow_read = []
allow_write = []
deny_read = []
deny_write = []

[sandbox.network]
allowed_domains = []
allow_local_binding = false
allow_unix_sockets = []
~~~

运行语义：

- TUI：sandbox 失败后可请求一次 unsandboxed fallback。
- headless/-p/schedule/SubAgent：sandbox 失败直接拒绝。
- allow_unsandboxed_commands=false 时任何 surface 都不得 fallback。
- fail_if_unavailable=true 时启动阶段直接失败。
- Bypass 只跳过询问，不跳过 sandbox。

### 5.3.6 统一 Bash runner

crates/tools/src/bash.rs 与 bash_session.rs 必须共用 SandboxRunner：

- 前台、后台命令使用相同 profile。
- 子进程继承边界。
- run_in_background 不得成为绕过路径。
- BashOutput/KillShell 只管理已在 sandbox 内启动的任务。
- 记录 sandbox backend、是否降级、允许域名和写根摘要。

### 5.4.3 ModelCatalog

## 5.6 RequestPlan 与 Provider 错误标准化

### 5.6.1 RequestPlan

Agent 不直接把所有 RequestOptions 原样交给 Provider，而是先生成：

~~~rust
pub struct RequestPlan {
    pub model: ModelIdentity,
    pub max_tokens: u32,
    pub reasoning: ReasoningRequest,
    pub tool_policy: ToolRequestPolicy,
    pub cache_policy: CachePolicy,
    pub stream_usage: bool,
    pub vision: bool,
    pub dropped_parameters: Vec<DroppedParameter>,
}
~~~

Provider 只序列化已由 capability resolver 判定支持的字段。

### 5.6.2 参数自动降级

当供应商返回明确 unsupported parameter：

1. 解析为 ProviderError::UnsupportedParameter。
2. 如果参数可安全移除，记录降级并仅重试一次。
3. 写入短期 capability cache。
4. TUI/headless 显示“已移除不兼容字段 X 后重试”。
5. 不对认证、工具语义和安全约束做自动降级。

### 5.6.3 ProviderError

~~~rust
pub enum ProviderErrorKind {
    Authentication,
    PermissionDenied,
    RateLimited,
    Overloaded,
    ContextLengthExceeded,
    UnsupportedParameter,
    InvalidRequest,
    InvalidToolSchema,
    StreamTruncated,
    Timeout,
    Network,
    SafetyBlocked,
    Unknown,
}
~~~

统一字段：

- kind
- provider_status
- retry_after
- retryable
- parameter
- request_id
- redacted_message

不得把完整响应、认证信息或潜在用户代码无界写入日志。

## 5.7 工具参数解析、修复和校验

### 5.7.1 RawToolCall

流式阶段先保留原始参数：

~~~rust
pub struct RawToolCall {
    pub id: String,
    pub name: String,
    pub raw_arguments: String,
}
~~~

只有经过 ToolArgumentPipeline 后才生成可执行 ToolCall。

### 5.7.2 Pipeline

~~~text
严格 JSON parse
    |
失败
    v
有限语法修复
    |
    v
再次 parse
    |
    v
JSON Schema validate
    |
失败
    v
生成精确错误反馈
    |
    v
模型定向重试
~~~

允许的修复：

- 去掉 Markdown 代码围栏。
- 去掉 JSON 前后的说明文本，但只有能唯一识别一个 JSON 对象时。
- 删除尾逗号。
- 补全可确定的闭合括号/引号。
- 修复 SSE 截断导致的末尾不完整，但不得猜字段值。

禁止的修复：

- 猜 file_path。
- 猜 Bash command。
- 把 null 变成空字符串。
- 自动选择 enum。
- 根据上下文生成 old_string/new_string。
- 给有副作用字段填默认值。

### 5.7.3 Schema validator

- 使用成熟 JSON Schema validator；实施前确认与 Rust 1.80 MSRV 兼容。
- ToolDefinition 在注册时预编译 schema。
- 无效的内置/MCP/Plugin schema 在暴露给模型前报告。
- required、type、enum、minimum/maximum、additionalProperties 等至少完整支持。
- 复杂 oneOf/anyOf 对能力较弱模型可生成简化 schema，但执行校验仍使用原始 schema。

### 5.7.4 定向重试

给模型的错误必须机器可读且简短：

~~~json
{
  "error": "tool_arguments_invalid",
  "tool": "Edit",
  "issues": [
    {"path": "$.file_path", "expected": "string", "actual": "missing"}
  ],
  "instruction": "Regenerate only this tool call. Do not execute another tool."
}
~~~

默认最多两次：

1. 原 schema + 精确错误。
2. 简化 schema + 强制单工具模式。

第二次仍失败则停止该工具调用，不能无限循环。

### 5.7.5 工具策略

按 ModelCapabilities 控制：

- 是否允许并行工具。
- 每轮最大工具数。
- 是否提供 tool_choice。
- 是否一次只允许一个工具。
- schema 是否简化。
- 工具失败后是否允许同模型重试。

## 5.8 国内模型 PromptPolicy

不为每个模型复制一整套不可维护的 system prompt，而是模块化：

- base agent contract
- tool-use contract
- planning contract
- safety contract
- provider/model quirk
- computer-use contract

PromptDialect 通过评测选择：

- concise English
- concise Chinese
- bilingual
- XML structured
- Markdown structured

原则：

- 不预设中文一定优于英文。
- 同一模型用 A/B 结果选择。
- 减少重复否定句。
- 工具参数要求靠 schema 和执行反馈，不只靠提示词。
- 稳定模块保持顺序，提升 prompt cache 命中。

## 6.1 ToolSearch 与 lazy schema

### 6.1.1 ToolCatalog

为每个工具建立紧凑索引：

- name
- one-line summary
- tags
- server/plugin/source
- read-only / side-effect
- required capabilities
- full schema loader

### 6.1.2 暴露策略

工具总数不超过阈值时保持现有全量模式，避免小集合额外调用。

超过阈值时默认只发送：

- Read
- Glob
- Grep
- AskQuestion
- ToolSearch
- 当前模式必须的少量工具

ToolSearch 返回 top-K 候选名称和短描述；模型选中后下一次请求注入完整 schema。

默认 K = 8，可按模型能力调整。

### 6.1.3 检索

v1.4.4 先采用本地、可解释检索：

- 名称匹配
- description/token BM25 或等价词法评分
- tag
- MCP server/plugin scope
- 最近成功工具加权

不把远程 embedding 作为基础依赖。

### 6.1.4 Sticky 规则

- 当前工具链已使用的工具保持到任务边界。
- 工具连续多轮未使用后卸载 schema。
- MCP 禁用/卸载后下一回合立即失效。
- 权限策略始终在真实注册表上执行，lazy schema 不能扩大权限。

- RateLimited

## 6.3 Checkpoint / Rewind MVP

### 6.3.1 Checkpoint 时机

- 每条真实用户消息提交前创建。
- Plan 审批切换执行模式前创建。
- 自动 fallback 不额外创建用户可见 checkpoint。
- 手动命令可创建命名 checkpoint。

### 6.3.2 Git 仓库快照

目标是不修改用户真实 index，也不要求工作区干净。

推荐使用临时 GIT_INDEX_FILE：

1. 从 HEAD 初始化临时 index。
2. 把当前工作树状态写入临时 index。
3. write-tree / commit-tree 创建仅用于 checkpoint 的 Git object。
4. 不 checkout、不 stash、不修改真实 index。
5. 记录 untracked、ignored 和超限文件处理结果。

恢复前展示：

- 受影响文件
- 新增/删除/修改
- 行数
- 当前文件是否在 checkpoint 后被用户再次修改

必须确认后才能恢复文件。

### 6.3.3 非 Git 目录

- 使用受限内容快照。
- 默认限制文件数量和总字节。
- 超限明确报告，不宣称完整可恢复。

### 6.3.4 恢复范围

~~~text
/rewind

1. conversation + files
2. conversation only
3. files only
~~~

恢复文件不自动恢复：

- 外部服务状态
- 数据库
- 已发送网络请求
- 已执行系统命令的非文件副作用
- computer-use 外部应用状态

### 6.3.5 存储

~~~text
~/.wyj-code/sessions/<session-id>.checkpoints/
  manifest.json
  <checkpoint-id>.json
~~~

SessionFile 新增可选字段，保持旧会话可加载：

- branch_parent_session_id
- branch_parent_checkpoint_id
- current_checkpoint_id

### 6.3.6 Session branch

~~~text
/branch <checkpoint-id>
wyj-code session branch <session-id> <checkpoint-id>
~~~

- 新 session id。
- 复制 checkpoint 前的对话。
- 文件默认不自动切换，用户可选择同时恢复。
- 原 session 保持不变。

## 十、安全威胁模型

必须覆盖：

### 10.1 恶意仓库

- CLAUDE.md、Skill、Plugin、Hook、MCP 配置诱导越权。

- 项目文件试图读取 home 凭证。

- 项目级配置只能收紧高风险安全项，不能静默关闭 sandbox。
- 项目 Hooks/Plugin/MCP 保持独立信任。
- Allow 不能覆盖 protected deny。

### 10.2 Prompt injection

- WebFetch/MCP/代码注释要求泄露 Key 或执行命令。
- 权限边界不能依赖模型是否遵循提示。

### 10.3 路径逃逸

- ../
- symlink
- case-insensitive path
- bind mount
- temp path
- Git submodule/worktree 边界

### 10.4 Shell 绕过

- 重定向。
- command substitution。
- heredoc。
- 解释器脚本。
- background process。
- shell alias/function。
