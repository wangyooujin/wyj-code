## 1. 目标

v1.5.0 已完成 v1.4.4 后续全部 P1/P2 与历史工作树修改整合，但首轮 GitHub Release Action 在 Linux 严格 Clippy 阶段失败，没有产出公开 Release 资产。v1.5.1 只做发布修复和已发现的国内模型工具调用兼容收口，不重写既有 tag：

- 保留 v1.5.0 已交付的 Managed Worktree、Workflow DAG、ACP/daemon、全局 Session Registry、CodeIndex/LSP、Plugin Runtime、Review/CI 与 TUI 整合。
- 修复 Linux-only `clippy::needless_return` 与平台条件编译 `dead_code`。
- 修复国内模型“能力目录声明单工具，但响应实际包含多个完整合法工具调用”时的拒绝/重试死循环。
- 重新完成本机、Linux/Rust 1.94、GitHub Release 和 Pages 全链路门禁。

## 2. 国内模型兼容语义

`max_tools_per_turn` 和 `parallel_tool_calls` 是模型生成能力与执行调度提示，不替代工具自身的安全边界。模型已经返回多个完整调用时：

1. 每个调用仍必须通过原始 JSON Schema、权限和 sandbox 校验。
2. `parallel_tool_calls = false` 时按到达顺序串行执行。
3. 不把超过能力提示的合法调用伪装成 `tool_limit_exceeded` 参数错误。
4. 只有真实 `InvalidArguments` 才计入连续参数校验失败熔断；未暴露 schema 等其他拒绝原因不污染该计数。
5. 必须为响应中的每个 `tool_use` 回填对应 `tool_result`，保持 Anthropic/OpenAI-compatible 工具续轮协议完整。

回归测试覆盖：

- 保守能力下两个完整调用确实串行执行。
- 连续三轮多个完整调用不会误触参数重试耗尽，并执行全部六个调用。

## 3. 跨平台修复

- Linux bubblewrap 未安装分支直接返回块表达式，满足 `clippy::needless_return`。
- `generation_for` 只在 macOS、Windows 或单元测试中编译，Linux 普通 library target 不再产生 `dead_code`；测试仍验证窗口身份与边界变化会改变 generation。
